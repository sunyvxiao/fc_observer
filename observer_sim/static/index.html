⚠️ 能力边界（降级说明）
  • 无交叉校验：无 syscall 佐证，事件完整性依赖 Agent 主动申报；
  • 无 L2/L3 阻断能力：仅风险提示，不执行内核级拦截；
  • Linux FIFO 实时监测 / 录制-回放 / eBPF 阻断为独立模式，Windows 下不可用。

📡 Qoder CN 监测（Hooks 确定性申报通道）

Qoder CN 通过 Hooks 确定性申报（.lingma/settings.json → qoder_hook_reporter.py → POST /api/hook-report） 与 MCP 申报工具双通道上报工具调用，申报进入统一管线（broker→collector→归一化/规则/评分/研判→审计）， 产出 ALLOW/ALERT/BLOCK 判定、风险报告与审计日志。配置集中管理于 config.yaml 的 mcp_report 段。

🔗 接入引导（真实 Qoder CN 接入）
  1. 启动监测（本页按钮 或 CLI: python observer.py menu → qoder → start）；
  2. 注册 MCP Server（可选通道）: 执行 qoder_integration/register_observer_mcp.sh <目标项目>，或 qoderclicn mcp add -t sse -s project observer http://127.0.0.1:8765/sse；
  3. 配置 Hooks 确定性申报: 目标项目 .lingma/settings.json 写入 PostToolUse/PostToolUseFailure 钩子（command 指向 scripts/qoder_hook_reporter.py，本仓库根目录已有现成模板）；
  4. 重启 Qoder CN 会话使 Hooks 生效，此后每次工具调用都会确定性触发申报。
