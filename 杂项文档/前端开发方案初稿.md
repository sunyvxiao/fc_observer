# 方寸观察者模拟学习系统 — Web 前端开发方案

> **技术路线**：Python 标准库 `http.server` + 原生 HTML/CSS/JS + SSE | **目标平台**：Windows 本地 | **依赖**：零新增 | **版本**：v1.0-web

---

## 第一部分：总览

### 1.1 一句话定义

在现有 CLI 演示系统（`demo.py`）基础上新增 Web 模式（`app.py`），使用 Python 标准库 `http.server` 提供 HTTP 服务 + SSE 实时推送，前端为单个 `index.html` 文件（HTML/CSS/JS 内联，零框架），核心业务逻辑（`observer_core/`）零改动，CLI 与 Web 并存。

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **零依赖** | 不新增任何 `pip install` 或 npm 包 |
| **全白盒** | ~700 行新增代码，全部可读可调试 |
| **不改核心** | `observer_core/`、`scenarios/`、`rules/`、`models/` 零改动 |
| **CLI 共存** | `python demo.py` 和 `python app.py` 各自独立运行 |
| **单文件前端** | 一个 `index.html`，浏览器直接打开源码即文档 |

### 1.3 前后端职责边界

### 2.2 核心数据流

```
用户点击 "运行场景 A01"
        │
        ▼
前端 JS:  fetch("/api/scenario/run", {method: "POST", body: {scenario_id: "a01"}})
        │
        ▼
后端:    收到 POST, 生成 run_id, 创建 Queue, 启动后台线程, 返回 {"run_id": "xxx"}
        │
        ▼
前端 JS: 收到 run_id, 立即创建 EventSource("/api/scenario/stream/xxx")
        │
        ▼
后端:    GET /api/scenario/stream/xxx → 进入 SSE 循环, 阻塞读取 Queue
        │
        ▼
后台线程: 执行场景逻辑:
           for each event in scenario:
               归一化 → 规则匹配 → 风险评分 → 研判 → 处置
               将步骤数据(JSON) put 到 Queue
        │
        ▼
SSE端点: 从 Queue get 到数据 → self.wfile.write("data: {...}\n\n") → flush
        │
        ▼
前端 JS: EventSource.onmessage → JSON.parse → 追加日志行到 #log-container
        │
        ▼
后台线程: 所有事件处理完毕 → put({"type": "done", "analysis_panel": {...}})
        │
        ▼
SSE端点: write("data: {type: done, ...}\n\n") → break → 关闭连接
        │
        ▼
前端 JS: onmessage 检测到 type==="done" → 渲染分析面板 → es.close()
```

### 2.3 线程模型

```
┌──────────────────────────────────────────────────────────────────┐
│                         线程模型                                  │
│                                                                  │
│  主线程 (MainThread)                                              │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  httpd.serve_forever()                                     │ │
│  │  循环: 接收 HTTP 请求 → do_GET/do_POST → 返回响应           │ │
│  │  对于 SSE 端点: 在 do_GET 内阻塞读取 Queue, 逐行 write      │ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                                  │
│  工作线程 (daemon=True, 每个场景一个)                             │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  def _run_scenario_async(scenario_id, event_queue):          │ │
│  │      runner = ScenarioRunner(...)                           │ │
│  │      for step_data in runner.run_stream():  # 生成器        │ │
│  │          event_queue.put(step_data)                         │ │
│  │      event_queue.put({"type": "done", "analysis": {...}})    │ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                                  │
│  关键数据结构:                                                    │
│  active_runs: dict[str, queue.Queue]  # run_id → 事件队列        │
│  run_results: dict[str, dict]         # run_id → 分析面板数据    │
└──────────────────────────────────────────────────────────────────┘
```

**为什么 HTTP 不超时？** `http.server` 的 SSE 端点会在 `do_GET` 方法内保持连接，直到场景运行完毕才返回。这是 HTTP/1.1 长连接的标准行为，不需要特殊配置。场景运行时长（每个场景几秒到几十秒）远低于浏览器默认超时（通常 30-120 秒可配置）。

#### GET `/api/scenario/stream/{run_id}`

```
响应: SSE (text/event-stream)

每条事件格式:
data: {"type":"step","seq":1,"event_type":"file_open","raw_input":"...","normalized":{...},"rule_match":{...},"risk_score":{...},"decision":{...},"disposal":{...}}

data: {"type":"step","seq":2,"event_type":"execve","raw_input":"...",...}

data: {"type":"done","analysis_panel":{...},"files_generated":[...]}

SSE 协议规范:
  · Content-Type: text/event-stream
  · Cache-Control: no-cache
  · Connection: keep-alive
  · 每条消息: "data: {JSON}\n\n"
  · 支持可选 event: 字段区分消息类型

实现:
  在 do_GET 方法中:
    1. 设置 SSE 响应头
    2. while True: data = event_queue.get(timeout=30)
    3. write SSE 格式数据 → flush
    4. 收到 "done" → break

对应 CLI: 逐个事件的 "[按 Enter 继续...]" 逐步展示
```

### 3.3 SSE 事件格式规范

```
SSE 事件类型:

1. 场景运行步骤事件:
   event: step
   data: {"type":"step","run_id":"...","seq":1,"event_type":"execve",...}

2. 场景完成事件:
   event: done
   data: {"type":"done","run_id":"...","analysis_panel":{...},"files_generated":[...]}

3. 批量运行 - 场景开始:
   event: scenario_start
   data: {"type":"scenario_start","scenario_id":"a01","name":"...","index":1,"total":12}

4. 批量运行 - 场景完成:
   event: scenario_done
   data: {"type":"scenario_done","scenario_id":"a01","analysis_panel":{...}}

5. 批量运行 - 全部完成:
   event: all_done
   data: {"type":"all_done","global_stats":{"total_scenarios":37,...}}

6. 心跳 (防止连接超时, 每15秒):
   event: heartbeat
   data: {"type":"heartbeat","timestamp":"..."}

7. 错误事件:
   event: error
   data: {"type":"error","message":"Scenario not found: xxx"}
```

async function runScenario(scenarioId, category) {
    // 1. 切换到场景运行视图
    showView("scenario-run");
    setScenarioHeader(scenarioId);

                state.eventSource.close();
                state.eventSource = null;
            },
            onError: (err) => {
                showError(`连接中断: ${err}`);
            }
        }
    );
}

## 第五部分：后端实现要点

### 5.1 关键设计决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| HTTP 服务器 | `http.server.HTTPServer` + 自定义 `BaseHTTPRequestHandler` | Python 标准库，零依赖 |
| 路由分发 | 在 `do_GET`/`do_POST` 中用 `urllib.parse.urlparse` 解析 path，if-elif 分发 | 简单透明，路由数 <20，不需要正则 |
| SSE 实现 | `self.wfile.write()` 逐行写入，`self.wfile.flush()` 强制发送 | `BaseHTTPRequestHandler` 原生支持 |
| 线程模型 | `threading.Thread(target=..., daemon=True)` + `queue.Queue()` | 标准库，线程安全 |
| 静态文件 MIME | 使用 `mimetypes.guess_type()` 自动检测 | 标准库，支持 HTML/CSS/JS/JSON/MD |
| 服务器关闭 | `POST /api/server/stop` → `httpd.shutdown()` | 优雅关闭 |

### 5.2 `do_GET` 路由分发结构

```
def do_GET(self):
    parsed = urllib.parse.urlparse(self.path)
    path = parsed.path
    params = urllib.parse.parse_qs(parsed.query)

    if path == "/":
        self._serve_static_file("static/index.html", "text/html")

    elif path == "/api/health":
        self._send_json({"status": "ok"})

    elif path == "/api/categories":
        self._send_json(get_categories())

    elif path == "/api/scenarios":
        category = params.get("category", [None])[0]
        self._send_json(get_scenarios(category))

    elif path.startswith("/api/scenario/stream/"):
        run_id = path.split("/")[-1]
        self._handle_sse_stream(run_id)

    elif path == "/api/scenario/run-all":
        category = params.get("category", [None])[0]
        self._handle_sse_run_all(category)

    elif path.startswith("/api/scenario/result/"):
        run_id = path.split("/")[-1]
        self._send_json(get_result(run_id))

    elif path == "/api/tests/stream":
        self._handle_sse_tests()

    elif path == "/api/reports/list":
        self._send_json(get_report_list())

    elif path == "/api/reports/view":
        file_path = params.get("path", [None])[0]
        self._serve_report_file(file_path)

    else:
        self._send_error(404, "Not Found")
```

### 5.3 SSE 端点实现要点

```python
def _handle_sse_stream(self, run_id):
    """SSE 事件流端点"""
    event_queue = active_runs.get(run_id)

    if not event_queue:
        self._send_error(404, f"Run ID not found: {run_id}")
        return

    # SSE 响应头
    self.send_response(200)
    self.send_header("Content-Type", "text/event-stream")
    self.send_header("Cache-Control", "no-cache")
    self.send_header("Connection", "keep-alive")
    self.send_header("Access-Control-Allow-Origin", "*")
    self.end_headers()

    try:
        while True:
            try:
                data = event_queue.get(timeout=30)  # 最长 30 秒无事件则心跳
            except queue.Empty:
                # 发送心跳
                self.wfile.write(f"event: heartbeat\ndata: {json.dumps({'type':'heartbeat'})}\n\n".encode())
                self.wfile.flush()
                continue

            event_type = data.get("type", "step")
            json_data = json.dumps(data, ensure_ascii=False, default=str)
            self.wfile.write(f"event: {event_type}\ndata: {json_data}\n\n".encode())
            self.wfile.flush()

            if event_type == "done":
                break

    except (BrokenPipeError, ConnectionResetError):
        pass  # 客户端断开连接
    finally:
        # 清理: 标记 run_id 已完成
        pass
```

def run_scenario_interactive(scenario_id):

def run_scenario_stream(scenario_id):

    for event in scenario.events:
        step_data = process_event_to_dict(event)
        yield step_data  # 由调用方 put 到 Queue

## 第八部分：边界条件与容错

| 场景 | 处理策略 |
|------|---------|
| 浏览器在场景运行中途关闭 | SSE 连接断开 → Python 捕获 `BrokenPipeError` → 后台线程继续执行完毕（不影响数据产出） |
| 多个浏览器 Tab 同时运行同一场景 | 每个 run 独立 run_id，互不干扰 |
| 场景运行超长（>30s 无新事件） | SSE 端点每 30s 发送 heartbeat，防止浏览器超时断开 |
| 请求不存在的 run_id | 返回 `{"error": "Run ID not found"}` + 404 |
| 请求不存在的场景 ID | 返回 `{"error": "Scenario not found: xxx"}` + 404 |
| 后台线程执行异常 | `try/except` 捕获 → `event_queue.put({"type": "error", ...})` → 前端显示错误 |
| 服务器端口被占用 | 启动时检测 `socket.error` → 提示用户更换端口或关闭占用进程 |
