# 方寸观察者模拟学习系统 — 项目描述

> 让每一个 AI Agent 的行为都可控、可追溯、可信赖

---

## 一、项目背景

### AI Agent 时代，行为监控为何至关重要？

随着 AI 大模型的快速发展，越来越多的企业开始部署 AI Coding Agent 来辅助软件开发。这些 Agent 能够自主编写代码、执行命令、访问文件系统，甚至进行网络通信。

然而，**自主性越强，风险越大**：

- **误操作风险**：Agent 可能执行危险命令（如删除系统文件），造成不可逆的损失
- **数据泄露风险**：Agent 可能读取敏感信息（如密钥、配置文件）并通过网络外传
- **串谋风险**：多个 Agent 可能协同作案——一个负责收集数据，另一个负责传输
- **信任缺失**：企业无法判断 Agent 的行为是否合规，缺乏有效的监管手段

**方寸观察者模拟学习系统**正是为解决这些问题而生。它模拟了真实生产环境中 AI Agent 行为监控系统的核心能力，展示了如何在不侵入 Agent 运行的前提下，实现全方位的行为观测、风险评估和主动防护。

## 二、系统能解决什么问题？

### 核心痛点与解决方案

| 痛点 | 我们的解决方案 |
|------|-------------|
| Agent 做了什么？无法感知 | **全链路行为采集**：每一条命令、每一次文件访问、每一个网络连接都被完整记录 |
| 哪些行为是危险的？难以判断 | **智能风险评分**：四维评估模型自动量化风险等级，从"低风险"到"紧急"一目了然 |
| 发现危险行为如何阻止？ | **三级梯度阻断**：从温和告警到强制终止，递进式防护策略兼顾安全与业务连续性 |
| 事后如何追溯？如何定责？ | **全链路审计**：每个决策都有据可查，每步操作都有因果链，生成可读的分析报告 |
| 多个 Agent 串谋怎么办？ | **跨 Agent 关联检测**：自动识别不同 Agent 之间的协同行为，发现隐藏的串谋模式 |

## 三、产品功能亮点

### 1. 无感知的行为观测

系统像一位"隐形观察者"，在 Agent 完全无感知的情况下，实时采集其所有行为：
- 执行了什么命令？
- 访问了哪些文件？
- 连接了什么网络地址？

所有行为数据通过安全通道传输，不影响 Agent 的正常运行。

### 2. 智能四维风险评估

不是简单的"黑名单"匹配，而是通过四个维度综合评估每个行为的风险程度：

- **规则命中**（40%）：是否触发了已知的危险模式？（如 `rm -rf /`、向可疑 IP 发送数据）
- **基线偏离**（25%）：与 Agent 的历史正常行为相比，是否异常？
- **上下文风险**（20%）：近期行为序列是否可疑？（如"先读密钥文件，再连接外部服务器"）
- **序列异常**（15%）：行为模式是否偏离正常规律？

综合评分从 0 到 1，自动划分为低/中/高/紧急四个风险等级。

### 3. 三级梯度阻断

采用"递进式"防护策略，在安全性和业务连续性之间取得最佳平衡：

| 级别 | 名称 | 处理方式 | 适用场景 |
|:---:|------|---------|---------|
| 1 | 软报告 | 操作正常执行，系统记录告警 | 中等风险行为，需要关注但不必阻止 |
| 2 | 阻止访问 | 操作被阻止，Agent 收到"权限不足"反馈 | 高危操作，需要立即制止 |
| 3 | 硬中断 | Agent 进程被强制终止 | 极端危险行为，必须立即停止一切活动 |

**智能升级机制**：如果同一个 Agent 短时间内多次触发低级告警，系统会自动升级处置力度——从"提醒"升级到"阻止"，再到"强制终止"。

### 4. 全链路审计与报告

每个行为从采集到处置的完整过程都会被记录：
- **审计日志**：结构化的 JSON 格式，便于程序化分析和合规审查
- **风险分析报告**：自动生成 Markdown 格式的可读报告，包含风险分布、阻断明细、规则统计
- **行为图谱**：以图结构展示 Agent 的行为序列和因果关系，支持跨 Agent 关联分析

### 5. 跨 Agent 串谋检测

当多个 Agent 在同一时间窗口内出现可疑的协同行为时，系统会自动建立关联关系，识别潜在的串谋模式。例如：
- Agent-A 读取了敏感文件
- 1 秒内，Agent-B 开始向外部服务器发送数据
- 系统自动检测并标记这种跨 Agent 的可疑关联

## 四、系统工作流程

系统的工作流程就像一条精密的"流水线"，每个行为从发生到处置，要经过七个站点的完整处理：

```
事件采集 → 归一化 → 规则匹配 → 风险评分 → 研判决策 → 阻断执行 → 审计输出
```

### 第一步：事件采集

系统通过底层探针（模拟 eBPF 技术）实时捕获 Agent 的系统调用行为。探针分为三类：
- **进程探针**：捕获命令执行（如 git clone、python run）
- **文件探针**：捕获文件操作（如读取、写入、删除）
- **网络探针**：捕获网络连接（如 HTTP 请求、DNS 查询）

### 第二步：归一化处理

原始事件被转换为统一的标准格式，同时补充上下文信息：
- 这个事件属于哪个 Agent？
- 这个 Agent 之前做了什么？
- 这个进程的父进程是谁？

### 第三步：规则匹配

将事件与预设的安全策略规则进行匹配。系统内置了 15 条安全规则，覆盖三大类：
- **命令执行规则**：识别危险命令（如删除、格式化、提权操作）
- **文件操作规则**：识别敏感文件访问（如密钥文件、配置文件）
- **网络规则**：识别可疑网络行为（如外联未知 IP、大流量传输）

### 第四步：风险评分

通过四维评估模型计算综合风险分数（0~1），并划分风险等级：
- **LOW**（< 0.3）：正常行为，无需干预
- **MEDIUM**（0.3 ~ 0.6）：需要关注，可能触发告警
- **HIGH**（> 0.6）：高风险，需要阻止或终止

### 第五步：研判决策

基于风险等级和规则匹配结果，通过研判矩阵做出最终决策：
- **ALLOW**（放行）：行为安全，允许继续执行
- **ALERT**（告警）：行为存在风险，记录并通知
- **BLOCK**（阻断）：行为危险，必须阻止

### 第六步：阻断执行

根据决策等级执行对应的处置动作：
- Tier1 软报告：放行 + 记录告警
- Tier2 阻止访问：阻止操作 + 返回权限错误
- Tier3 硬中断：终止 Agent 进程 + 紧急保存证据

### 第七步：审计输出

所有处理结果被完整记录：
- 写入 JSON 审计日志（每步操作都有据可查）
- 更新行为图谱（记录行为间的因果关系）
- 生成风险分析报告（供安全团队审阅）

## 五、三级梯度阻断的业务意义

传统的安防系统往往是"非黑即白"——要么全部放行，要么全部阻止。但实际业务中，过于激进的阻断会影响正常业务，过于宽松则可能放过真正的威胁。

**三级梯度阻断**提供了一种更灵活、更智能的防护策略：

### Tier1 软报告 —— "我知道，我记录"

- **业务影响**：零。Agent 的操作正常完成
- **系统动作**：记录审计日志，更新风险画像
- **业务价值**：不干扰正常业务，同时积累行为数据用于后续分析

### Tier2 阻止访问 —— "这个不行"

- **业务影响**：当前操作被阻止，但 Agent 仍可继续其他操作
- **系统动作**：返回权限错误，记录阻断原因
- **业务价值**：精准阻止危险操作，不影响 Agent 的整体工作流程

### Tier3 硬中断 —— "立即停止一切活动"

- **业务影响**：Agent 被强制终止
- **系统动作**：终止进程树，紧急保存所有证据，生成事故报告
- **业务价值**：在极端情况下（如数据正在被外传），以最快的速度止损

### 自动升级机制

系统会追踪每个 Agent 的违规历史。如果同一个 Agent 在短时间内反复触发告警，处置力度会自动升级：

```
第 1-2 次告警 → Tier1 软报告（观察期）
第 3 次告警   → 自动升级到 Tier2（阻止访问）
被阻止 2 次后 → 自动升级到 Tier3（强制终止）
```

这种"先礼后兵"的策略，既给了 Agent 改正的机会，也确保了持续违规时能够果断处置。

## 七、技术架构概览

系统采用**分层设计**，各层职责清晰，通过标准化接口通信：

```
┌─────────────────────────────────────────────┐
│         Web 可视化层 (app.py)                 │
│   深色终端主题 + SSE 实时推送 + 报告管理      │
│   基于 Python 标准库，零 pip install 依赖     │
└──────────────────┬──────────────────────────┘
                   │ HTTP + SSE
                   v
┌─────────────────────────────────────────────┐
│            C++ 探针模拟层                     │
│   模拟 eBPF 内核探针，采集系统调用事件        │
│   通过命名管道与 Python 层双向通信             │
└──────────────────┬──────────────────────────┘
                   │ 双向命名管道
                   │ (事件上报 + 指令下发)
                   v
┌─────────────────────────────────────────────┐
│          Python 业务逻辑层                    │
│                                              │
│  监测层 → 评判层 → 阻断层 → 审计层           │
│                                              │
│  虚拟时钟：驱动全系统时间判定                  │
│  自优化接口：为后续迭代预留扩展点              │
└─────────────────────────────────────────────┘
```

**核心设计特点**：

- **全链路透明**：每个处理阶段的输入输出均可查看、可追溯
- **模块可替换**：评分算法、阻断策略、输出格式均可独立替换
- **零外部依赖**：Python 仅需一个第三方库（pyyaml），C++ 仅需标准库，Web 模式无需 npm/框架
- **数据本地化**：所有数据存储在本地文件，不依赖网络，不上传云端
- **双模式并存**：命令行模式（demo.py）和 Web 模式（app.py）各自独立，核心引擎共享零改动
