### 2.5 核心接口说明

#### ICollector 抽象接口（`collector/base_collector.py`）

所有采集方案必须实现此接口。上层通过此接口与采集层交互，不关心底层实现。

```python
class ICollector(ABC):
    def capabilities(self) -> CollectorCapabilities: ...
    def attach(self, target_pid: int = 0, agent_id: str = "") -> bool: ...
    def start(self) -> Iterator['RawEvent']: ...
    def send_command(self, cmd: 'Command') -> bool: ...
    def detach(self) -> None: ...
    def get_process_tree(self) -> dict: ...
```

**各方法在不同模式下的行为**：

| 方法 | Simulation | Strace（待实现） | eBPF（待实现） |
|------|-----------|:---:|:---:|
| `capabilities()` | name="Simulation", can_block=True | name="Strace", can_block=False | name="Ebpf", can_block=False (v1) |
| `attach(pid, id)` | 忽略 pid，返回 True | `Popen(["strace", "-p", pid])` | libbpf 加载+挂载探针 |
| `start()` | 读 YAML → yield RawEvent | 逐行解析 strace → yield RawEvent | perf ring buffer → yield RawEvent |
| `send_command()` | 返回 True（模拟成功） | 返回 False（不支持） | 返回 False（v1 不支持） |
| `detach()` | 清理场景状态 | `subprocess.terminate()` | 卸载 eBPF 程序+清理 maps |
| `get_process_tree()` | 返回 `{}` | 从 `/proc/{pid}/stat` 构建 | 从 `/proc/{pid}/stat` 构建 |

#### CollectorCapabilities 数据类

```python
@dataclass
class CollectorCapabilities:
    name: str                       # "Simulation" | "Strace" | "Ebpf"
    can_observe: bool               # 是否支持观测
    can_block_tier2: bool           # 是否支持 Tier2 阻断（返回 EPERM）
    can_block_tier3: bool           # 是否支持 Tier3 阻断（终止进程）
    is_transparent: bool            # 对 Agent 是否无感知
    performance_overhead: str       # "low" | "medium" | "high"
    time_source: str                # "virtual" | "realtime_monotonic"
```

#### detect_and_create_collector() 工厂函数（`adapter/platform_detect.py`）

```python
def detect_and_create_collector(config: dict, mode_override: str = None):
    """
    优先级: mode_override > config["mode"] > "auto"
    
    auto 模式在 Linux 上的决策链:
      _check_ebpf_capability() == True  → EbpfCollector
      ↓ False
      StraceCollector 可导入            → StraceCollector
      ↓ ImportError
      SimulationCollector（最终降级）
    """
```

**此函数已完成全部模式路由逻辑**（simulation/ebpf/strace/auto），Linux 端只需实现 `EbpfCollector` 和 `StraceCollector` 类，工厂函数通过延迟导入自动发现。

### 3.1 Day 5：eBPF execve 探针（4h）

**任务**：

| 子任务 | 时间 | 内容 |
|--------|:----:|------|
| `ebpf/observer.bpf.c` execve 探针 | 2h | 挂载 `tracepoint/syscalls/sys_enter_execve`；捕获 filename, argv（`bpf_probe_read_user_str`）；`bpf_perf_event_output` 推送事件；填充 `event_t` 结构体（含 timestamp_ns/pid/ppid/comm） |
| `ebpf/Makefile` + 编译验证 | 1h | 生成 vmlinux.h: `bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h`；编译: `clang -target bpf -g -O2 -I. -c observer.bpf.c -o observer.bpf.o`；验证加载: `bpftool prog load observer.bpf.o /sys/fs/bpf/observer_exec` |

**event_t 结构体定义**（内核态与用户态共享，已在定稿 §3.2 中定义）：

```c
struct event_t {
    u64  timestamp_ns;       // bpf_ktime_get_ns()
    u32  pid;                // bpf_get_current_pid_tgid() >> 32
    u32  ppid;               // 从 task_struct 读取
    u32  uid;                // 从 task_struct 读取
    u8   event_type;         // 0=execve, 1=openat, 2=connect
    u8   blocked;            // 第一版固定为0
    u16  padding;
    union {
        struct { char filename[256]; char argv[512]; } exec;
        struct { char filename[256]; u32  flags; } file;
        struct { u32  ip_addr; u16  port; u8   protocol; } net;
    };
    char comm[16];            // bpf_get_current_comm
};
```

**交付标准**：`observer.bpf.o` 编译成功，`bpftool` 验证加载无错误，运行 `ls` 能捕获 execve 事件。

### 3.3 Day 7：Python eBPF 加载器（4h）

**任务**：`collector/ebpf_collector.py` — 实现 `EbpfCollector(ICollector)`

**核心实现要点**：

1. **libbpf ctypes 绑定**：
   - `bpf_object__open` / `bpf_object__load` / `bpf_program__attach`
   - `bpf_map__fd` / `perf_buffer__new` / `perf_buffer__poll` / `perf_buffer__free`

2. **perf ring buffer 消费**：`perf_buffer__new` 注册回调，`perf_buffer__poll(timeout_ms)` 轮询

3. **`_to_raw_event()` 字段映射**（按定稿 §3.3）：

   | event_t 字段 | RawEvent 字段 | 转换逻辑 |
   |---|---|---|
   | `timestamp_ns` | `timestamp_ns` | 直接赋值（u64→int） |
   | `event_type` (u8: 0/1/2) | `event_type` (str) | `{0:"exec", 1:"file_open", 2:"net_conn"}` |
   | `pid` | `pid` | 直接赋值 |
   | `ppid` | `ppid` | 直接赋值 |
   | — | `event_id` | 自增计数器 `f"ebpf_evt_{seq:06d}"` |
   | — | `agent_id` | 从 `config.ebpf.target_agent_id` 读取（默认 "observed-agent"） |
   | — | `agent_framework` | 固定为 `"ebpf"` |
   | `exec.filename` | `executable` | `bytes.decode('utf-8', errors='replace')` |
   | `exec.argv` | `arguments` | 按 `\0` 分割 → list[str] |
   | `file.filename` | `file_path` | `bytes.decode` |
   | `file.flags` | `file_op` | `{0:"read", 1:"write", 2:"write"}` |
   | `net.ip_addr` | `remote_addr` | `socket.inet_ntoa(struct.pack('!I', ip))` |
   | `net.port` | `remote_port` | `socket.ntohs(port)` |
   | `net.protocol` | `protocol` | `{0:"TCP", 1:"UDP"}` |

4. **线程模型**：`perf_buffer__poll` 在独立线程轮询 + `queue.Queue` 解耦，避免阻塞主处理循环

5. **生命周期**：`attach()` → 加载+挂载，`detach()` → 卸载+清理 maps，`atexit` 注册清理函数

6. **`send_command()`**：空实现，返回 False，日志记录 "eBPF 阻断将在第二版实现"

7. **`capabilities()` 返回值**：
   ```python
   CollectorCapabilities(
       name="Ebpf", can_observe=True,
       can_block_tier2=False,    # 第一版不支持
       can_block_tier3=False,    # 第一版不支持
       is_transparent=True,      # 对 Agent 无感知
       performance_overhead="low",
       time_source="realtime_monotonic",
   )
   ```

**单元测试**（`tests/test_ebpf_collector.py`）：
- `_to_raw_event()` 字段映射（构造 mock event_t → 验证 RawEvent）
- 生命周期管理（attach/detach 状态转换）
- `send_command()` 返回 False + 日志记录

**交付标准**：Python 加载器成功加载 `.bpf.o` + 消费事件；手动运行 `ls/cat/curl`，`ebpf_collector` 能捕获其 execve/openat/connect。

### 4.4 事件格式一致性验证（0.5h）

- `executable`/`file_path`/`remote_addr` 为字符串
- `arguments` 为字符串列表或 None
- `timestamp_ns` 为整数（eBPF 是 monotonic clock，模拟是 VirtualClock，`observer_core/` 不关心时钟类型）

## 6. 已知注意事项

### 6.1 延迟导入机制

`platform_detect.py` 中 `detect_and_create_collector()` 对 `EbpfCollector` 和 `StraceCollector` 使用**延迟导入**（`from collector.ebpf_collector import EbpfCollector`）。这意味着：

- Linux 端只需创建 `collector/ebpf_collector.py` 和 `collector/strace_collector.py`，工厂函数**自动生效**，无需修改 `platform_detect.py`
- 如果对应模块不存在，会触发 `ImportError`，工厂函数捕获后执行降级逻辑

### 6.2 config.yaml 已预留配置段

```yaml
ebpf:
  bpf_object_path: "ebpf/observer.bpf.o"    # EbpfCollector 读取此路径加载 .bpf.o
  target_pid: null                            # 运行时 --pid 参数覆盖
  target_agent_id: "observed-agent"           # RawEvent.agent_id 默认值
  perf_buffer_page_count: 64                  # perf ring buffer 大小
  heartbeat_interval_sec: 15

strace:
  strace_binary: "/usr/bin/strace"            # strace 可执行文件路径
  trace_syscalls: "execve,openat,connect,unlink,sendto"
  target_pid: null
```

### 6.3 eBPF 第一版仅做观测

根据定稿，**eBPF 第一版不支持阻断**（`bpf_override_return` 不支持 tracepoint 的技术限制）。因此：
- `EbpfCollector.send_command()` 返回 `False`，日志记录 "eBPF 阻断将在第二版实现"
- `EbpfCollector.capabilities().can_block_tier2` = `False`
- eBPF Maps 只需 `BPF_MAP_TYPE_PERF_EVENT_ARRAY`（事件推送），不需要 `block_policy` map

### 6.4 时间戳差异

- eBPF 使用 `bpf_ktime_get_ns()`（monotonic clock，从系统启动开始计时）
- 模拟模式使用 VirtualClock（场景控制的虚拟时间）
- `observer_core/` 只读取 `timestamp_ns` 字段值，**不关心时钟类型**，两种时间源可共存

Phase 1-2 完成后的测试基线为 **181 个测试**（130 原有 + 23 adapter + 28 simulation_collector）。Phase 3 新增的 `test_ebpf_collector.py` 和 `test_strace_collector.py` 应在此基础上继续累加，不应导致任何现有测试失败。

## 附录：RawEvent 数据模型参考

`EbpfCollector._to_raw_event()` 和 `StraceCollector._parse_line()` 产出的 RawEvent 必须与以下定义完全一致：

```python
@dataclass
class RawEvent:
    event_id: str                # 如 "ebpf_evt_000001" / "strace_evt_000001"
    timestamp_ns: int            # 纳秒时间戳
    event_type: str              # "exec" | "file_open" | "net_conn"
    pid: int
    ppid: int
    agent_id: str                # 从 config 读取
    agent_framework: str         # "ebpf" / "strace"
    # 以下字段按事件类型填充，未使用字段为 None
    executable: Optional[str] = None       # exec 事件
    arguments: Optional[List[str]] = None  # exec 事件
    file_path: Optional[str] = None        # file_open 事件
    file_op: Optional[str] = None          # "read" | "write" | "delete" | "rename"
    remote_addr: Optional[str] = None      # net_conn 事件
    remote_port: Optional[int] = None      # net_conn 事件
    protocol: Optional[str] = None         # "TCP" | "UDP"
```
