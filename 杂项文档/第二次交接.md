### 2.5 eBPF 探针技术要点

#### event_t 结构体（`ebpf/observer.bpf.c`）

```c
struct event_t {
    u64  timestamp_ns;       // bpf_ktime_get_ns()
    u32  pid;                // bpf_get_current_pid_tgid() >> 32
    u32  ppid;               // 从 task_struct 读取
    u32  uid;                // current_uid_val
    u8   event_type;         // 0=execve, 1=openat, 2=connect
    u8   blocked;            // 第一版固定为0
    u16  padding;
    union {
        struct { char filename[256]; char argv[512]; } exec;
        struct { char filename[256]; u32  flags; } file;
        struct { u32  ip_addr; u16  port; u8   protocol; } net;
    };
    char comm[16];            // bpf_get_current_comm
};
```

**关键实现决策**：`event_t` 结构体超过 512 字节 BPF 栈限制（实际约 800 字节），使用 `BPF_MAP_TYPE_PERCPU_ARRAY` 作为事件缓冲区，通过 `bpf_map_lookup_elem` 获取指针后填充字段，避免栈溢出。

#### 三个 tracepoint 挂载点

| 探针 | 挂载点 | 捕获的关键参数 |
|------|--------|--------------|
| execve | `tracepoint/syscalls/sys_enter_execve` | `ctx->args[0]` → filename, `ctx->args[1]` → argv |
| openat | `tracepoint/syscalls/sys_enter_openat` | `ctx->args[1]` → filename, `ctx->args[2]` → flags |
| connect | `tracepoint/syscalls/sys_enter_connect` | `ctx->args[1]` → sockaddr（IP:Port） |

#### _to_raw_event() 字段映射（`collector/ebpf_collector.py`）

| event_t 字段 | RawEvent 字段 | 转换逻辑 |
|---|---|---|
| `timestamp_ns` | `timestamp_ns` | 直接赋值（u64→int） |
| `event_type` (u8: 0/1/2) | `event_type` (str) | `{0:"exec", 1:"file_open", 2:"net_conn"}` |
| `pid` | `pid` | 直接赋值 |
| `ppid` | `ppid` | 直接赋值 |
| — | `event_id` | 自增计数器 `f"ebpf_evt_{seq:06d}"` |
| — | `agent_id` | 从 `config["ebpf"]["target_agent_id"]` 读取（默认 "observed-agent"） |
| — | `agent_framework` | 固定为 `"ebpf"` |
| `exec.filename` | `executable` | `bytes.decode('utf-8', errors='replace')` |
| `exec.argv` | `arguments` | 按 `\0` 分割 → list[str]（使用 `ctypes.memmove` 读取完整缓冲区） |
| `file.filename` | `file_path` | `bytes.decode` |
| `file.flags` | `file_op` | `{flags & 0x2 or flags & 0x1: "write", else: "read"}` |
| `net.ip_addr` | `remote_addr` | `socket.inet_ntoa(struct.pack('!I', ip))` |
| `net.port` | `remote_port` | `socket.ntohs(port)` |
| `net.protocol` | `protocol` | `{0:"TCP", else:"UDP"}` |

#### capabilities() 返回值对比

| 字段 | SimulationCollector | StraceCollector | EbpfCollector |
|------|:---:|:---:|:---:|
| `name` | `"Simulation"` | `"Strace"` | `"Ebpf"` |
| `can_observe` | `True` | `True` | `True` |
| `can_block_tier2` | `True` | `False` | `False` |
| `can_block_tier3` | `True` | `False` | `False` |
| `is_transparent` | `False` | `False` | `True` |
| `performance_overhead` | `"low"` | `"medium"` | `"low"` |
| `time_source` | `"virtual"` | `"realtime_monotonic"` | `"realtime_monotonic"` |

## 5. 已知问题与注意事项

### 5.1 eBPF 第一版仅做观测

根据定稿，**eBPF 第一版不支持阻断**（`bpf_override_return` 不支持 tracepoint 的技术限制）。因此：
- `EbpfCollector.send_command()` 返回 `False`，日志记录 "eBPF 阻断将在第二版实现"
- `EbpfCollector.capabilities().can_block_tier2` = `False`
- `EbpfCollector.capabilities().can_block_tier3` = `False`
- eBPF Maps 只需 `BPF_MAP_TYPE_PERCPU_ARRAY`（事件缓冲区）+ `BPF_MAP_TYPE_PERF_EVENT_ARRAY`（事件推送），不需要 `block_policy` map

### 5.2 eBPF 加载需要 sudo 权限

`EbpfCollector.attach()` 需要 root 权限加载 eBPF 程序到内核。在 Linux 上需要：
```bash
sudo python3 main.py --mode ebpf --pid <TARGET_PID>
```
或者配置 `CAP_BPF` + `CAP_PERFMON` 能力。

### 5.3 strace 模式性能开销

`StraceCollector` 的 `performance_overhead` 为 `"medium"`，因为 strace 通过 ptrace 系统调用跟踪目标进程，会对目标进程产生明显的性能影响。在对性能敏感的场景中建议优先使用 eBPF 模式。

### 5.4 时间戳差异

| 模式 | 时间源 | 说明 |
|------|--------|------|
| 模拟模式 | `VirtualClock`（场景 YAML 的 `delay_ms` 推进） | 虚拟时间，从 `virtual_clock.start_ns` 开始 |
| strace 模式 | `time.time_ns()`（纳秒精度） | 真实系统时间 |
| eBPF 模式 | `bpf_ktime_get_ns()`（内核 monotonic clock） | 从系统启动开始计时 |

**关键设计**：`observer_core/` 只读取 `RawEvent.timestamp_ns` 字段值，**不关心时钟类型**。三种时间源可共存，不影响核心处理链路。

### 5.5 配置键名不一致（待修复）

`config.yaml` 中 `strace.strace_binary` 与 `strace_collector.py` 中读取的 `strace_bin` 键名不一致。代码使用 `.get("strace_bin", "strace")` 带默认值，功能不受影响，但建议统一。
