## 0. 现状基线（与差距清单一致）

已落地（无需再开发）：A1（提示词 v2.0 合规留痕定位）、A4（连接器重连指引）、P1~P6（规则修复 + 研判矩阵修订 2.1 + 会话化违规升级 + 三态统计口径）。

| 项 | 内容 |
|---|---|
| 目标 | 实测 WorkBuddy 是否支持 PreToolUse/PostToolUse 钩子及 PreToolUse 阻止语义，决定第 2 层实现范围 |
| 前置 | 无（与第 1 层并行） |
| 实施落点 | 验证活动，产出《WorkBuddy Hook 支持性验证报告》（建议置于本目录） |

| 验收标准 | 验证报告形成，每项结论附真实会话证据（截图/申报留痕），并明确回填差距清单 Q3 状态 |

### T2.1 PreToolUse 同步闸门（P2 回注，BLOCK 升级为真实拦截）

| 项 | 内容 |
|---|---|
| 目标 | 凡要执行的工具调用同步经过观察者判定，BLOCK 时回注 `{"decision":"block"}` 阻止执行——覆盖 WorkBuddy 判据的「分歧区」（如项目自定义红线 R007b/R013 等） |
| 现状 | 观察者侧 `hook_ingest` 摄入配置已存在（`config.yaml` 的 `mcp_report.hook_ingest`，`POST /api/hook-report`，缺省 disabled 行为不变）；`qoder_report_gateway.py` 已标注「P2 阻断联动预留」；simulate 已支持 `hook_event_name="PreToolUse"` 构造 pre 申报。**无同步判定回注** |
| 前置 | T2.0 验证通过（WorkBuddy 支持 PreToolUse 阻止语义） |
| 实施落点 | `observer_sim/mcp_bridge/server.py`（hook-report 端点同步响应扩展）+ `observer_sim/collector/mcp_report_collector.py`（或独立拦截决策模块，保持管线零改动）+ `observer_sim/monitor_daemon.py`（统计与留痕） |
| 具体内容 | ① PreToolUse 申报进入统一判定管线后，将判定结果同步回注为 `{"decision":"block"/"allow"}`（响应超时预算 ≤5s，与 `adapter/agent_bridge.py` 的 pre_tool 超时约定同源）；② 失效语义默认 **fail-open**（超时/服务不可用时放行并告警留痕），`config.yaml` 提供 `fail_closed` 选项，选择责任如实写入报告；③ 新增独立拦截决策留痕 `intercept_decisions.jsonl`：每次 PreToolUse 询问的判定、规则依据、耗时、超时标记——作为三轨溯源证据之一；④ daemon 统计与摘要增加 intercept 计数 |
| 预估成本 | 大（差距清单 P2 已标「大」） |
| 验收标准 | ① smoke 扩展 PreToolUse 序列：BLOCK 场景回注 block 且留痕完整；② 判定超时场景按 fail-open 处理并留痕告警；③ 拦截决策留痕可逐条溯源（事件→规则→判定→回注结果）；④ 误拦/漏拦回归用例通过（ALERT 场景回 allow，不误伤）；⑤ 全量回归不回归 |

### T2.2 PostToolUse 确定性钩子（覆盖从「模型意愿」升级为「框架确定性」）

| 项 | 内容 |
|---|---|
| 目标 | 由框架强制触发每次工具调用后的申报，消除「Agent 自主不申报」盲区（对齐 Qoder CN Hooks 通道思路） |
| 现状 | 观察者侧 hook-report 摄入端点已支持 PostToolUse（Qoder 通道已验证 `qoder.yaml` 的 PostToolUse 摄入）；WorkBuddy 侧无 Hook 注册机制证据（待 T2.0 验证） |
| 前置 | T2.0 验证通过（WorkBuddy 支持 PostToolUse 类钩子） |
| 实施落点 | WorkBuddy 侧 Hook 注册配置（按 T2.0 验证结论确定形态）+ `observer_sim/mcp_bridge/server.py`（如需 WorkBuddy 专用映射）+ 触发率监控 |
| 具体内容 | ① 为 WorkBuddy 注册 PostToolUse 钩子，工具调用后框架自动向 hook-report 申报（无需提示词引导）；② 触发率监控：统计「会话内工具调用数 vs hook 申报数」偏差，偏差超阈值在报告与日志告警「钩子失效/被绕过」；③ 与提示词申报并存（双源去重或同源判定，判定管线仍零改动） |
| 预估成本 | 中（依 T2.0 结论浮动） |
| 验收标准 | ① 真实会话中每次工具调用均产生 PostToolUse 申报（触发率统计实证）；② 未加载提示词场景下申报仍完整（与 T1.2 无关依赖）；③ 断连场景偏差告警可检测；④ 若 T2.0 结论为不支持 → 本任务关闭并记录平台边界 |

## 5. 边界与「暂不做」事项

1. **不引入 ETW / 内核驱动级检测**：syscall 全量观测与真实内核阻断不在本计划内（对应 Linux eBPF 能力，Windows 侧定位为长期技术选型，另行评估）；
2. **不改动判定管线**：规则引擎、风险评分、研判矩阵（修订 2.1）、违规升级逻辑零改动；本计划所有判定相关变更仅限于「接入侧触发方式」与「产出层呈现」；
3. **不描述未实现能力**：第 2 层 T2.1/T2.2 仅在 T2.0 验证通过后启动；验证未通过前，对外文档（使用说明书/README）不得出现「已具备真实拦截」表述；
4. **跨会话关联（Q1）与时序聚合（Q2）不在本计划**：需可信时间戳与长周期数据，独立立项；
5. **申报覆盖不等于行为覆盖**：三层改进提升的是发现与暴露能力，不改变「Agent 行为完整性在 Agent 侧」的权责边界（见使用说明书「责任声明与溯源依据」章节）。
