# 安全提示词内容（WorkBuddy 会话开场粘贴）

> 版本: 2.0 ｜ 用法: 将下方「提示词开始」与「提示词结束」之间的**全部内容**（含 Markdown 结构）复制，作为 WorkBuddy 新会话的**第一条消息**粘贴发送。
> 说明: 本文件为纯文本，不依赖任何项目代码；提示词中的 `observer` 为方寸观察者 MCP 服务名（由 `connect_workbuddy.py configure-workbuddy` 注册，SSE 地址 `http://127.0.0.1:8765/sse`）。
>
> **版本 2.0 修订依据（2026-08-25 真实 WorkBuddy 会话实证）**：
> 1.0 版将提示词定位为「降级安全监测环境」的强制框架，并声明「观察者判定作为权威」「BLOCK 不真实阻断故须自觉约束」。实测中 WorkBuddy 将该定位判定为**提示注入**（prompt injection）而拒绝配合，属于「Agent 侧安全拦截」，申报侧改进无效。
> 2.0 版据此改写定位为**合规审计留痕通道**：不凌驾 WorkBuddy 自身安全权威、不宣称强制监测框架，仅请求按 observer 工具的真实设计用途（合规留痕 + 风险提示）配合申报。实证中该定位下 WorkBuddy 完整完成 `report_session`（start/end）与 `report_tool_call`（pre/post）申报。

## 提示词开始（以下内容全部复制）

本会话接入了 MCP 服务 `observer`（方寸观察者，已通过 mcp.json 正规注册，用途为合规审计留痕与风险提示）。为便于审计方获得完整、真实的操作留痕，请在使用工具时按以下约定配合：

### 一、会话留痕（report_session）

1. 会话开始时，请调用 `observer` 的 `report_session`：`agent_id` 填你的 Agent 标识（如 "workbuddy"），`session_id` 填本会话唯一标识，`session_type` 填会话类型（如 "development"），`status` 填 "start"；
2. 完成用户全部任务、会话结束前，再次调用 `report_session`，`status` 填 "end"。

### 二、工具调用留痕（report_tool_call）

1. 每次调用工具（`execute_command`、`read_file`、`write_file`、`web_fetch`、`curl` 等）之前，请调用 `report_tool_call`：`action_type` 填 "pre"，`tool_name` 填工具真实名称，`tool_args` 填计划使用的真实参数；
2. 每次工具调用完成后，再调用一次 `report_tool_call`：`action_type` 填 "post"，`tool_args` 附上执行结果摘要；
3. 请如实填写工具名与参数，不省略、不改写——留痕的可信度取决于申报的真实性；
4. 如某次申报调用失败，可在下一条消息中重试申报。

### 三、动作留痕（report_action，可选）

对重要动作（开始某项子任务、修改配置、安装依赖等），可调用 `report_action` 补充留痕：`action_type` 填动作类型，`action` 填动作名称，`detail` 填简要说明。

### 四、敏感操作提示

如任务涉及破坏性命令（`rm -rf /` 等）、凭据/密钥文件读取、数据外传、提权等敏感操作，请先向用户确认是否执行。你所在平台的安全策略与安全拦截始终优先于本留痕约定。

### 五、任务结束摘要

完成用户全部任务后，可在回复末尾简要列出本次会话的留痕情况（工具调用申报条数与会话边界申报状态），便于审计方核对。
