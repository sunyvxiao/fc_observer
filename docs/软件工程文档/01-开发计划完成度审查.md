## 三、技术路线变更对照

| 决策点 | 开发方案定稿 | 当前实际 | 变更原因 |
|--------|-----------|---------|---------|
| 目标平台 | **Windows 单机** | **Windows + Linux 双平台** | 对标产品（Fangcun Observer）本身是 Linux eBPF 方案，仅 Windows 模拟不够完整 |
| 采集层架构 | C++ 探针直接通过命名管道输出 | **ICollector 抽象接口 + 6 种实现** | 支持多平台（模拟/eBPF/strace/DeepAgent/文件回放），架构更灵活 |
| C++ 探针定位 | 核心运行时组件 | **保留兼容，退居次选** | Windows 模拟模式仍可用，但主路径改为 Python SimulationCollector |
| eBPF 阻断 | 开发方案未涉及（仅定义为"接口预留"） | **eBPF v2.0 已实现真实阻断** | `ebpf/observer.bpf.c` 含 kprobe + bpf_override_return |
| 管道通信 | 双向命名管道（Windows） | **FIFO + 采集器直连双路径** | 模拟模式通过 ICollector 直接 yield 事件，不再依赖管道；守护模式通过 FIFO |
| 时间源 | VirtualClock 统一使用 | **VirtualClock + RealtimeClock 双源** | 采集模式决定了时间源：模拟用虚拟时钟，eBPF/strace 用真实时钟 |
| Web 模式 | 未规划 | **app.py + SSE 完整实现** | 提升演示效果和可用性 |
| DeepAgent 集成 | 未规划 | **AgentBridge + HookRegistry** | 扩展 AI Agent 框架集成能力 |
