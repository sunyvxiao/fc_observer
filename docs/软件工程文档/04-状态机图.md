# 状态机图

> 描述系统核心实体的状态转换。所有状态机以当前实际代码为基准。
> 文档日期：2026 年 7 月 30 日

## 一、Monitor 守护进程生命周期状态机

```mermaid
stateDiagram-v2
    [*] --> INIT: 进程启动
    INIT --> STARTING: 加载配置/config.yaml
    STARTING --> RUNNING: 管道就绪+采集器初始化完成
    STARTING --> ERROR: 初始化失败
    ERROR --> STOPPING: 自动清理
    RUNNING --> STOPPING: 收到 SIGTERM/SIGINT<br/>或 MonitorLifecycleManager.stop()
    STOPPING --> STOPPED: 管道关闭+采集器停止+资源释放
    STOPPED --> [*]

    state RUNNING {
        [*] --> IDLE: 等待事件
        IDLE --> COLLECTING: 管道有新数据/采集器 yield
        COLLECTING --> PROCESSING: RawEvent 到达
        PROCESSING --> IDLE: 事件处理完成
        PROCESSING --> PROCESSING: 连续处理事件
    }
```

**状态说明**：

| 状态 | 描述 | 触发条件 | 执行动作 |
|------|------|---------|---------|
| INIT | 进程启动，尚未加载配置 | 进程入口 | 解析命令行参数 |
| STARTING | 加载配置，初始化各子系统 | `MonitorLifecycleManager.start()` | 加载 config.yaml → 创建管道 → 初始化采集器 → 启动核心 Pipeline |
| RUNNING | 正常运行，处理事件 | 初始化成功 | 进入事件循环（IDLE/COLLECTING/PROCESSING） |
| ERROR | 初始化失败 | 管道创建失败、采集器初始化失败 | 记录错误日志，尝试降级 |
| STOPPING | 正在关闭 | 信号或 `stop()` 调用 | 发送停止信号 → 等待事件处理完成 → 清理资源 |
| STOPPED | 已完全停止 | 清理完成 | 进程退出 |

## 二、场景运行状态机

```mermaid
stateDiagram-v2
    [*] --> PENDING: 场景加载
    PENDING --> PREPARING: 解析 YAML/初始化 Pipeline
    PREPARING --> RUNNING: 开始执行事件序列
    PREPARING --> FAILED: 加载/初始化异常
    RUNNING --> RUNNING: 处理单个事件<br/>(delay_ms 等待)
    RUNNING --> PAUSED: 用户暂停 (Web 模式)
    PAUSED --> RUNNING: 用户恢复
    RUNNING --> COMPLETED: 所有事件处理完成
    RUNNING --> FAILED: 未捕获异常
    RUNNING --> CANCELLED: 用户取消
    COMPLETED --> [*]: 输出报告
    FAILED --> [*]: 错误日志
    CANCELLED --> [*]: 部分结果保存
```

**状态说明**：

| 状态 | 触发 | 产物 |
|------|------|------|
| PENDING | 用户选择场景 | — |
| PREPARING | 点击运行 | Normalized Pipeline 实例化、BaselineChecker 初始化 |
| RUNNING | Pipeline 就绪 | 逐事件：归一化→规则匹配→评分→研判→阻断→审计 |
| PAUSED | 用户暂停 | 保留当前进度和状态 |
| COMPLETED | 事件序列耗尽 | 审计日志、风险报告、基线快照、行为图谱 |
| FAILED | 异常 | 错误日志、部分审计记录 |
| CANCELLED | 用户取消 | 部分结果保存 |

## 三、Agent 违规升级状态机

```mermaid
stateDiagram-v2
    [*] --> CLEAN: Agent 首次注册
    CLEAN --> TIER1_MONITORING: 首次违规 (Decision != ALLOW)
    
    state TIER1_MONITORING {
        [*] --> COUNTING: 记录 Tier1 违规
        COUNTING --> COUNTING: 窗口内新增 Tier1 违规
        COUNTING --> WINDOW_EXPIRE: 5分钟窗口过期<br/>计数器清零
        WINDOW_EXPIRE --> COUNTING: 新违规
    }
    
    TIER1_MONITORING --> TIER2_ESCALATED: Tier1 累计 ≥5 次
    
    state TIER2_ESCALATED {
        [*] --> COUNTING2: 记录 Tier2 违规
        COUNTING2 --> COUNTING2: 窗口内新增 Tier2 违规
        COUNTING2 --> WINDOW_EXPIRE2: 5分钟窗口过期
        WINDOW_EXPIRE2 --> COUNTING2: 新违规
    }
    
    TIER2_ESCALATED --> TIER3_TERMINATED: Tier2 累计 ≥3 次
    
    TIER3_TERMINATED --> [*]: Agent 进程终止<br/>后续事件直接丢弃
```

**核心参数**（从 `AgentViolationTracker` + `tuning.yaml`）：

| 参数 | 默认值 | 说明 |
|------|:---:|------|
| WINDOW_SIZE_NS | 300,000,000,000 (5分钟) | 虚拟时钟滑动窗口 |
| TIER1_ESCALATE_THRESHOLD | 5 | Tier1 累计次数 → 升级 Tier2 |
| TIER2_ESCALATE_THRESHOLD | 3 | Tier2 累计次数 → 升级 Tier3 |

**Agent 终止后行为**：

```mermaid
stateDiagram-v2
    ACTIVE --> TERMINATED: Tier3 硬中断执行
    TERMINATED --> [*]: 后续事件被 BlockingCoordinator 直接丢弃<br/>返回 BlockingResult(blocked=true, tier=TIER3)
```

## 四、基线模型冷热状态机

```mermaid
stateDiagram-v2
    [*] --> COLD_START: BaselineChecker 初始化
    COLD_START --> WARMING: 开始收集事件 (collect)
    WARMING --> WARMING: total_events < min_warm_events<br/>偏离分固定 0.0
    WARMING --> WARMED: total_events ≥ min_warm_events
    WARMED --> WARMED: 持续收集+偏离检测生效
    
    COLD_START --> LOADED: load_baseline(filepath)
    LOADED --> WARMED: 已有基线数据 (is_warm=true)
    LOADED --> WARMING: 基线未预热 (is_warm=false)

    WARMED --> COLD_START: reset() 重置
```

**冷启动行为**：
- `BaselineChecker.is_cold_start == True` 时
- `BaselineChecker.compute_deviation()` → 固定返回 `0.0`
- `BasicBaselineScore.score()` 检查 `baseline.get("is_warm")` → 冷启动返回 `0.0`
- `BasicSequenceScore.score()` 检查 `context.event_count < min_events` → 冷启动返回 `0.0`

## 五、事件处理决策状态机（研判矩阵 + 自动升级）

```mermaid
stateDiagram-v2
    [*] --> SCORED: RiskAssessment 完成
    SCORED --> MATRIX_LOOKUP: 进入 DecisionEngine
    
    state MATRIX_LOOKUP {
        [*] --> CHECK_KEY: (risk_level, rule_action)
        CHECK_KEY --> ALLOW: (LOW, *) / (MEDIUM, allow)
        CHECK_KEY --> ALERT: (MEDIUM, block/alert) / (HIGH, allow)
        CHECK_KEY --> BLOCK_TIER2: (HIGH, block/alert)
    }
    
    ALLOW --> AUTO_ESCALATE: score ≥ 0.6 ?
    ALERT --> AUTO_ESCALATE: score ≥ 0.9 ?
    BLOCK_TIER2 --> AUTO_ESCALATE: score ≥ 0.9 ?
    
    AUTO_ESCALATE --> FINAL_ALLOW: 无需升级
    AUTO_ESCALATE --> FINAL_ALERT_TIER2: score ≥ 0.6, tier=Tier1 → 升级
    AUTO_ESCALATE --> FINAL_BLOCK_TIER3: score ≥ 0.9 → 强制升级
    
    FINAL_ALLOW --> EXECUTE: 执行 Tier1 SoftReport
    FINAL_ALERT_TIER2 --> EXECUTE: 执行 Tier2 BlockAccess
    FINAL_BLOCK_TIER3 --> EXECUTE: 执行 Tier3 HardInterrupt
    
    EXECUTE --> [*]: 审计记录
```

**研判矩阵**（3×3）：

| 风险等级 \ 规则动作 | 命中 block | 命中 alert | 未命中 (allow) |
|:---:|:---:|:---:|:---:|
| **HIGH** | BLOCK @ TIER2 | BLOCK @ TIER2 | ALERT @ TIER1 |
| **MEDIUM** | ALERT @ TIER1 | ALERT @ TIER1 | ALLOW @ TIER1 |
| **LOW** | ALLOW @ TIER1 | ALLOW @ TIER1 | ALLOW @ TIER1 |

**自动升级覆盖**：

| 条件 | 覆盖结果 |
|------|---------|
| `overall_score ≥ 0.9` | 强制 BLOCK @ TIER3（忽略矩阵结果） |
| `overall_score ≥ 0.6` 且当前 TIER1 | 升级到 ALERT @ TIER2 |

## 六、采集器连接状态机

```mermaid
stateDiagram-v2
    [*] --> DISCONNECTED: 初始状态
    DISCONNECTED --> CONNECTING: 启动采集器
    CONNECTING --> CONNECTED: 管道/FIFO 连接成功<br/>或 Generator 就绪
    CONNECTING --> DISCONNECTED: 连接超时/失败
    CONNECTED --> DISCONNECTED: 管道断开/采集器异常
    DISCONNECTED --> CONNECTING: 自动重连 (守护进程模式)
    
    state CONNECTED {
        [*] --> STREAMING: 正常接收事件
        STREAMING --> RECONNECTING: 心跳超时
        RECONNECTING --> STREAMING: 心跳恢复
        RECONNECTING --> DISCONNECTED: 超过最大心跳丢失次数
    }
```

**心跳机制**（Command.HEARTBEAT）：

| 参数 | 值 | 说明 |
|------|:---:|------|
| heartbeat_interval_ms | 1000 | 心跳发送间隔 |
| heartbeat_max_miss | 3 | 最大未响应次数（超过则断开） |

## 七、全局风险等级状态机

```mermaid
stateDiagram-v2
    [*] --> LOW: overall_score < 0.3
    LOW --> MEDIUM: 0.3 ≤ score < 0.6
    MEDIUM --> HIGH: 0.6 ≤ score < 0.9
    HIGH --> CRITICAL: score ≥ 0.9
    MEDIUM --> LOW: score < 0.3
    HIGH --> MEDIUM: score < 0.6
    CRITICAL --> HIGH: score < 0.9
```

**评分阈值**（从 `config.yaml` + `RiskAssessment.score_to_level()`）：

| 评分范围 | 风险等级 | 典型触发场景 |
|---------|:---:|------|
| [0.0, 0.3) | LOW | 正常开发操作、合法命令 |
| [0.3, 0.6) | MEDIUM | 边界操作、非标准端口、Unknown package install |
| [0.6, 0.9) | HIGH | 危险命令、敏感文件访问、sudo 提权 |
| [0.9, 1.0] | CRITICAL | 反弹 Shell、rm -rf /、已知恶意 IP |
