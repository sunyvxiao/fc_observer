> **版本**：v1.0 | **维护日期**：2026-07-31
>
> 本文档描述测试体系的架构、分类、运行方式和编写规范。

## 一、测试体系总览

```
┌─────────────────────────────────────────────────────────────────┐
│                     统一测试入口 test.py                          │
│   python test.py [--unit|--collector|--integration|--scenario   │
│                    |--e2e|--web|--all|--check|--list]            │
└──────────┬───────────┬──────────┬──────────┬──────────┬─────────┘
           │           │          │          │          │
     ┌─────▼─────┐ ┌──▼────┐ ┌──▼─────┐ ┌──▼─────┐ ┌─▼──────┐
     │ 单元测试   │ │采集器 │ │集成测试│ │场景测试│ │端到端  │
     │ (pytest)  │ │测试   │ │(pytest)│ │(YAML)  │ │(shell) │
     │           │ │(pytest)│        │ │        │ │        │
     │ 7 文件    │ │7 文件 │ │2 文件  │ │37 场景 │ │run_all │
     │ 136 cases │ │172    │ │58     │ │        │ │30 项   │
     └───────────┘ └───────┘ └────────┘ └────────┘ └────────┘
     
     无需 root    无需 root  无需 root  无需 root   需 root
```

### 测试分层

| 层级 | 名称 | 目的 | 运行频率 |
|------|------|------|---------|
| L1 | 单元测试 | 验证单个模块/类的内部逻辑 | 每次代码修改 |
| L2 | 采集器测试 | 验证各采集器（simulation/strace/ebpf/replay）的数据输入 | 每次采集器修改 |
| L3 | 集成测试 | 验证多模块协作的 Pipeline 正确性 | 每次提交 |
| L4 | 场景测试 | 验证 37 个 YAML 场景的完整运行结果 | 发布前 |
| L5 | 端到端测试 | 验证真实 strace/eBPF 环境下的系统行为 | 环境变更后 |
| L6 | Web 测试 | 验证 Web API 和 SSE 推送功能 | Web 功能修改后 |

## 三、统一入口 `test.py` 使用方法

### 3.1 命令行参数

```bash
# 交互式菜单（推荐日常使用）
python test.py

# 运行指定分类
python test.py --unit              # 仅单元测试
python test.py --collector         # 仅采集器测试
python test.py --integration       # 仅集成测试
python test.py --scenario          # 仅场景测试（37 个 YAML 回放）
python test.py --e2e               # 仅端到端测试（需 root）
python test.py --web               # 仅 Web API 测试

# 组合运行
python test.py --unit --collector --integration   # 单元+采集器+集成
python test.py --all               # 全部（自动跳过不可用项）

# 辅助命令
python test.py --check             # 检测环境能力
python test.py --list              # 列出所有测试分类及状态
python test.py --filter n01        # 场景过滤（仅运行匹配的 ID）
```

### 3.2 环境自动检测

`test.py` 启动时自动检测以下能力，不可用时对应测试自动跳过：

| 检测项 | 影响 | 检测方式 |
|--------|------|---------|
| root 权限 | e2e 测试 | `os.geteuid() == 0` |
| strace 安装 | e2e 中的 strace 子项 | `shutil.which("strace")` |
| BTF 支持 | eBPF 测试 | `/sys/kernel/btf/vmlinux` 存在 |
| libbpf 可用 | eBPF 测试 | `ctypes.CDLL("libbpf.so")` 成功 |
| Web App 运行 | Web 测试 | HTTP 请求 `localhost:8080` |

### 3.3 测试输出

所有测试结果输出到 `observer_sim/output/` 目录：

```
output/
├── test_report/          ← test.py 汇总报告
│   ├── report_YYYYMMDD_HHMMSS.txt   ← 文本报告
│   ├── report_YYYYMMDD_HHMMSS.json  ← JSON 报告
│   ├── latest.txt        ← 最新报告（始终覆盖）
│   └── latest.json
├── unit_test/            ← pytest 单元测试结果
│   ├── test_results.json
│   └── test_output.txt
├── audit/                ← 场景运行的审计日志
├── reports/              ← 场景运行的风险分析报告
└── baselines/            ← 基线快照
```

## 四、各类测试的运行方式

### 4.1 单元测试 & 采集器测试 & 集成测试

```bash
# 通过 test.py（推荐）
python test.py --unit --collector --integration

# 直接 pytest
cd observer_sim
python -m pytest tests/test_monitoring.py -v
python -m pytest tests/ -v                    # 全部
```

**前置条件**：Python 3.10+、pyyaml、pytest
**预期耗时**：~10 秒（全部 ~366 个用例）

### 4.2 场景测试

```bash
# 通过 test.py（推荐）
python test.py --scenario

# 单个场景
python observer_sim/main.py --mode simulation --scenario n01

# 全部分类
python observer_sim/main.py --mode simulation --category normal
python observer_sim/main.py --mode simulation --category anomalous
```

**前置条件**：同单元测试
**预期耗时**：~2 分钟（37 个场景）

### 4.3 端到端测试

```bash
# 通过 test.py（推荐）
sudo python test.py --e2e

# 直接运行脚本
sudo bash sudo_test/run_all.sh
```

**前置条件**：root 权限 + strace + eBPF 环境（libbpf ≥ 1.4）
**预期耗时**：~1 分钟（30 项检查）

### 4.4 Web API 测试

```bash
# 先启动 Web 服务
python observer_sim/app.py &

# 运行测试
python test.py --web

# 或手动
python observer_sim/test_api.py
python observer_sim/test_sse.py
```

## 五、新增测试的编写规范

### 5.1 文件命名规则

| 类型 | 命名模式 | 位置 |
|------|---------|------|
| 单元测试 | `test_<module>.py` | `observer_sim/tests/` |
| 采集器测试 | `test_<collector_name>_collector.py` | `observer_sim/tests/` |
| 集成测试 | `test_<feature>_integration.py` | `observer_sim/tests/` |
| 场景 YAML | `<prefix><number>_<snake_name>.yaml` | `observer_sim/scenarios/<category>/` |
| e2e 测试 | 追加到 `sudo_test/run_all.sh` | `sudo_test/` |

### 5.2 单元测试模板

```python
"""
test_xxx.py — <模块名称> 测试

测试内容:
1. <功能点 1>
2. <功能点 2>
"""

import unittest
import sys
import os

sys.path.insert(0, os.path.join(os.path.dirname(__file__), ".."))


class TestXxx(unittest.TestCase):
    
    def setUp(self):
        """每个测试前的初始化"""
        pass
    
    def test_basic_functionality(self):
        """验证基本功能"""
        # Arrange
        # Act
        # Assert
        pass


if __name__ == "__main__":
    unittest.main()
```

### 5.3 场景 YAML 模板

```yaml
scenario:
  id: "<category><number>"
  name: "<场景名称>"
  description: "<设计目的>"
  expected_result: "<期望结果>"
  
  agents:
    - agent_id: "<agent-id>"
      framework: "<framework>"
      initial_pid: 10001
      
  event_sequence:
    - seq: 1
      delay_ms: 0
      agent: "<agent-id>"
      type: "exec"          # exec | file_open | net_conn
      executable: "/usr/bin/xxx"
      arguments: ["arg1"]
      
  expected:
    decision_count: {allow: N, alert: N, block: N}
    max_score_below: 0.3
    rule_not_hit: ["R001"]
```

### 5.4 添加流程

1. **编写测试文件**：按命名规则放入 `observer_sim/tests/`
2. **本地验证**：`python -m pytest tests/test_xxx.py -v`
3. **注册到 test.py**：在 `get_categories()` 的对应分类 `files` 列表中添加文件名
4. **全量验证**：`python test.py --all` 确保无回归

## 六、测试输出清理策略

| 目录 | 清理时机 | 清理方式 |
|------|---------|---------|
| `output/unit_test/` | 每次 pytest 运行前 | `conftest.py` 自动清空 |
| `output/test_report/` | 手动 | 保留最近 10 份，旧文件手动删除 |
| `output/audit/` | 手动 | 场景运行的审计日志，按需清理 |
| `output/reports/` | 手动 | 风险分析报告，按需清理 |
| `/tmp/observer_unit_test/` | 系统重启 | conftest 写入的临时回退目录 |

## 七、约束

- **observer_core/、models/、scenarios/、rules/ 零改动**：测试代码不得修改这些目录下的文件
- 测试代码仅操作 `tests/`、`sudo_test/`、项目根目录和 `杂项文档/`
- 不删除任何现有测试，只做归类和入口整合
