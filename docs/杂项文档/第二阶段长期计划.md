### 阶段 3 加固待办：分层日志生产加固项（待规划/未实施）

> 来源：阶段 3 分层日志金字塔验收后的分层规则评估（对照 syslog severity/facility、ELK 热温冷分层、Loki label 流、审计日志按天滚动与保留策略、WAL/segment compaction 实践）。
> 状态：全部为“待规划/未实施”；不影响阶段 3 验收结论，作为后续阶段规划依据。
> 注：评估中的第 ④ 项（anomaly 阈值硬编码未与 tuning 联动）已在本轮实施（`rollup.anomaly_score_threshold` 联动，ReportCacheManager 构造注入），故不在下表。

| 序 | 事项 | 优先级判断 | 原始描述与改进方向 |
|---|---|---|---|
| ① | L1/rollup 转存文件缺失时间键与保留策略 | 重要（长期运行无限增长风险） | `seg_XXXX.json`、`rollup_{seg_id}.jsonl` 仅有序号无日期前缀，`cache/segments/`、`cache/rollup/` 长期运行会无限增长（rollup 转存文件从不清理）。改进方向：文件名加日期前缀 `seg_{YYYYMMDD}_{seq}.json`；为 `cache/rollup/`、`cache/l2/` 增加保留天数（L2 温层保留 N 天，L3 冷层永久）。 |
| ② | 无压缩策略 | 中（体积优化，非正确性问题） | L2/L3 JSON 产物无任何压缩（无 gzip/zstd）。改进方向：为 L2/L3 落盘增加 `compress: true` 开关（audit 场景读取频率低、压缩体积收益大）。 |
| ③ | L0 缺少 schema 版本号 | 中（结构演进会破坏下钻索引） | L0 audit JSONL 无格式版本标记，L3 下钻索引依赖 `event_id` 字段，若 AuditEntry 结构演进无版本标记将破坏索引。改进方向：L0 文件名或首行 meta 增加 schema 版本，与 L1/L2/L3 的 `format_version` 对齐。 |
| ⑤ | L3 缺少 day_complete 完整性标记 | 中（partial 天语义未显式化） | L3 由 24 个 L2/天汇总，partial 天（l2_count<24）无显式完整性标记，下游易把 partial L3 误作全天审计；另 L1 段按 start_ns 整段归属小时桶（事件级未按各自时间戳分桶），60s 段跨小时概率低可接受但建议记录约束。改进方向：L3 增加 `day_complete: true/false` 字段。 |

## 四、关键结论

1. 核对修正了报告的 8 处状态判断：HookRegistry 模块与 hook_configs/ 已实现（报告称"未接线的半成品"，实际只差 agent_bridge 接线一步）；阻断借道 eBPF 已实现（报告称改进点，实为已有能力）；tuning 热加载已实现且四组件已接入（U2 只剩收尾）；n01 基线快照已实现（U9 已完成一半）；以及新增 K1/K2 两个报告未覆盖的真实缺陷。
2. 最大风险点排序：K1（测试体系当前在 Windows 不可用，一切回归验证的地基）> 三处编排漂移（U1/U2）> L-T4 数据丢失缺陷 > 图谱 O(n²)。
3. 主线必需项：阶段 0~4 的 ◆ 项共约 20 项；可裁剪项：T11/T12（先纯统计生成规则）、T18（先 CLI 审核）、MCP 全通道、H3、G2、B/C 合并、T14 可最后收口。
4. 并行性：阶段 1 的 U 系列与 L 系列互不依赖可双轨推进；阶段 2 的 T1/T2/T4 三层可并行推进；T17 与 T15/T16 并行；T19 贯穿设计、测试收口。
5. 全程不触碰 observer_core 检测语义的项只有 U 系列（纯输出层）；其余各项均涉及实时环，需以"每阶段结束全量回归 + Web/CLI 判定一致"为硬门禁。
