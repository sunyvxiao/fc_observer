# 录制-回放功能使用说明

> **版本**：v1.0  
> **更新日期**：2026-08-01  
> **适用对象**：方寸观察者模拟学习系统用户  
> **前置依赖**：`observer_sim/recorder/` 模块、`test.py` 统一测试入口

---

## 一、功能概述

录制-回放（Record-Replay）功能用于捕获 Agent 运行时的事件流，并支持事后重放分析。

**核心流程**：

```
录制阶段：
  Agent 运行 → 系统收到"开始录制"指令 → 采集并记录事件流 → 收到"结束录制"指令 → 持久化录制文件

回放阶段：
  用户选择历史录制 → 系统加载录制数据 → 通过 observer_core 处理链路重放 → 输出风险报告 + 审计记录
```

**关键特性**：

| 特性 | 说明 |
|------|------|
| 会话级管理 | 每次录制创建独立目录（`records/<YYYYMMDD_HHMMSS>/`） |
| 格式兼容 | 录制文件（`events.jsonl`）与 `FileReplayCollector` 完全兼容 |
| 全链路分析 | 回放经过 EventNormalizer → RuleEngine → RiskScorer → DecisionEngine → BlockingCoordinator → AuditLogger |
| 零改动约束 | 不修改 `observer_core/`、`models/`、`scenarios/`、`rules/` 目录 |

## 二、目录结构

所有录制数据存放在项目根目录下的 `records/` 文件夹中：

```
records/
├── 20260801_171849/              # 录制时间戳目录（YYYYMMDD_HHMMSS）
│   ├── meta.yaml                 # 录制元信息（开始/结束时间、采集模式、事件总数等）
│   ├── events.jsonl              # 事件数据（每行一个 JSON 对象，符合 RawEvent 字段定义）
│   └── replay_output/            # 回放分析输出（仅回放后生成）
│       ├── audit/                # 结构化审计记录（JSONL 格式）
│       │   └── audit_recorded_replay_*.jsonl
│       ├── reports/              # 风险报告（Markdown 格式）
│       │   └── risk_report_recorded_replay_*.md
│       ├── graphs/               # 行为图谱（JSON 格式）
│       │   └── graph_recorded_replay.json
│       └── replay_summary.json   # 回放摘要（统计数据）
└── ...
```

**文件说明**：

| 文件 | 格式 | 说明 |
|------|------|------|
| `meta.yaml` | YAML | 录制元数据（开始时间、结束时间、持续时长、采集模式、事件总数、agent_id 等） |
| `events.jsonl` | JSONL | 事件流数据（每行一个 JSON 对象，格式符合 `外部测试信息接入接口说明.md` 规范） |
| `replay_summary.json` | JSON | 回放统计（Allow/Alert/Block 计数、报告路径、图谱路径等） |
| `risk_report_*.md` | Markdown | 风险分析报告（由 `ReportExporter` 生成） |
| `audit_*.jsonl` | JSONL | 结构化审计日志（由 `AuditLogger` 生成） |
| `graph_*.json` | JSON | 行为图谱（由 `BehaviorGraph` 生成） |

### 3.3 Python API 模式

支持编程接口调用，适合集成到自定义脚本：

#### 录制 API

```python
import sys
sys.path.insert(0, 'observer_sim')

from recorder.session_recorder import SessionRecorder
from models.event import RawEvent

# 创建录制器
recorder = SessionRecorder(
    records_dir='records',           # 录制数据根目录
    agent_id='my-agent',             # Agent 标识
    collect_mode='simulation',       # 采集模式（simulation/strace/ebpf）
)

# 开始录制
recorder.start()
print(f"Session: {recorder.session_id}")
print(f"Dir: {recorder.session_dir}")

# 写入事件（可多次调用）
event = RawEvent(
    event_id="evt_001",
    timestamp_ns=1718092800000000000,
    event_type="exec",
    pid=12345, ppid=12344,
    agent_id="my-agent",
    agent_framework="recorded",
    executable="/usr/bin/curl",
    arguments=["curl", "-s", "https://example.com"],
)
recorder.write_event(event)

# 或从 ICollector 录制事件流
# recorder.record_from_collector(collector, max_events=100, timeout_s=60)

# 停止录制
summary = recorder.stop()
print(f"Events: {summary['event_count']}")
print(f"File: {summary['events_file']}")
```

#### 回放 API

```python
import sys
sys.path.insert(0, 'observer_sim')

from recorder.replay_engine import ReplayEngine

# 创建回放引擎
engine = ReplayEngine(config={})  # 可传入 config.yaml 配置

# 执行回放
result = engine.replay(
    session_dir='records/20260801_171849',  # 录制会话目录
    agent_id='replay-agent',                 # 回放 Agent 标识
)

# 查看结果
print(f"Total: {result['total']}")
print(f"Allow: {result['allow']}")
print(f"Alert: {result['alert']}")
print(f"Block: {result['block']}")
print(f"Report: {result['report_path']}")
print(f"Graph: {result['graph_path']}")
```

#### 列出历史录制

```python
from recorder.session_recorder import SessionRecorder

recordings = SessionRecorder.list_recordings('records')
for rec in recordings:
    print(f"{rec['session_id']}  {rec['event_count']} events  {rec['collect_mode']}")
```

## 四、事件格式规范

录制的 `events.jsonl` 文件格式完全兼容 `外部测试信息接入接口说明.md` 中定义的 JSONL 规范。

**每行一个 JSON 对象**，字段定义如下：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|:---:|------|
| `event_type` | string | **是** | 事件类型：`"exec"` / `"file_open"` / `"net_conn"` |
| `event_id` | string | 否 | 事件唯一标识（默认自动生成） |
| `timestamp_ns` | int | 否 | 纳秒时间戳（默认 0） |
| `pid` | int | 否 | 进程 ID（默认 0） |
| `ppid` | int | 否 | 父进程 ID（默认 0） |
| `agent_id` | string | 否 | Agent 标识（默认取录制器配置值） |
| `agent_framework` | string | 否 | 数据来源标识（默认 `"recorded"`） |
| `executable` | string | 否 | 可执行文件路径（exec 事件） |
| `arguments` | string[] | 否 | 命令行参数列表（exec 事件） |
| `file_path` | string | 否 | 文件路径（file_open 事件） |
| `file_op` | string | 否 | 文件操作（file_open 事件）：`read`/`write`/`delete`/`rename`/`chmod` |
| `remote_addr` | string | 否 | 远程地址（net_conn 事件） |
| `remote_port` | int | 否 | 远程端口（net_conn 事件） |
| `protocol` | string | 否 | 传输协议（net_conn 事件）：`TCP`/`UDP` |

**最小必填字段**仅为 `event_type`，其余字段均有默认值。

**示例**：

```jsonl
{"event_id": "rec_001", "timestamp_ns": 1718092800000000000, "event_type": "exec", "pid": 50001, "ppid": 50000, "agent_id": "my-agent", "agent_framework": "recorded", "executable": "/usr/bin/curl", "arguments": ["curl", "-s", "https://example.com"], "file_path": null, "file_op": null, "remote_addr": null, "remote_port": null, "protocol": null}
{"event_id": "rec_002", "timestamp_ns": 1718092800100000000, "event_type": "net_conn", "pid": 50001, "ppid": 50000, "agent_id": "my-agent", "agent_framework": "recorded", "executable": null, "arguments": null, "file_path": null, "file_op": null, "remote_addr": "192.168.1.100", "remote_port": 443, "protocol": "TCP"}
```

## 五、模块架构

录制-回放功能通过新增 `observer_sim/recorder/` 模块实现，不修改 `observer_core/`、`models/`、`scenarios/`、`rules/` 目录。

### 5.1 模块结构

```
observer_sim/
├── recorder/                       # 新增：录制-回放模块
│   ├── __init__.py                 # 模块导出（SessionRecorder + ReplayEngine）
│   ├── session_recorder.py         # 会话级录制管理器（338 行）
│   └── replay_engine.py            # 回放编排引擎（255 行）
├── collector/
│   ├── event_recorder.py           # 事件录制器（Windows 端已实现，211 行）
│   └── file_replay_collector.py    # 文件回放采集器（已有，复用）
└── observer_core/                  # 核心引擎（零改动）
```

### 5.2 核心类说明

#### SessionRecorder（会话级录制管理器）

**职责**：管理完整的录制会话（目录创建、元信息写入、事件录制）。

**关键方法**：

| 方法 | 说明 |
|------|------|
| `start()` | 开始录制，创建 `records/<timestamp>/` 目录，初始化 `EventRecorder` |
| `stop()` | 停止录制，写入 `meta.yaml`，返回录制摘要 |
| `write_event(event)` | 写入单个 `RawEvent` 到 `events.jsonl` |
| `record_from_collector(collector, max_events, timeout_s)` | 从 `ICollector` 录制事件流（透明包裹迭代器） |
| `list_recordings(records_dir)` | 静态方法，列出所有历史录制（按时间倒序） |

**属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `session_id` | str | 录制会话 ID（时间戳格式：`YYYYMMDD_HHMMSS`） |
| `session_dir` | str | 录制会话目录路径 |
| `is_recording` | bool | 是否正在录制 |
| `event_count` | int | 已录制的事件数 |
| `events_path` | str | `events.jsonl` 文件路径 |

#### ReplayEngine（回放编排引擎）

**职责**：加载录制文件 → observer_core 全链路处理 → 输出报告。

**关键方法**：

| 方法 | 说明 |
|------|------|
| `replay(session_dir, agent_id)` | 回放指定录制会话，生成风险分析报告 |

**处理链路**：

```
FileReplayCollector.load_data_file(events.jsonl)
    ↓
FileReplayCollector.start() → yield RawEvent
    ↓
EventNormalizer.normalize(raw)
    ↓
RuleEngine.match(norm)
    ↓
BaselineChecker.collect(norm)
    ↓
RiskScorer.assess(norm, match_result, agent_ctx)
    ↓
DecisionEngine.decide(assessment, event_id, agent_id)
    ↓
BlockingCoordinator.execute(norm, decision)
    ↓
BehaviorGraph.add_event(...)
    ↓
AuditLogger.log_event(...)
    ↓
ReportExporter.export_scenario_report(...)
```

### 6.4 与真实采集器集成（strace/eBPF）

```python
import sys, yaml
sys.path.insert(0, 'observer_sim')

from collector.strace_collector import StraceCollector
from recorder.session_recorder import SessionRecorder

# 创建 strace 采集器
config = yaml.safe_load(open('observer_sim/config.yaml'))
collector = StraceCollector(config)
collector.attach(target_pid=12345, agent_id='real-agent')

# 创建录制器

    records_dir='records',
    agent_id='real-agent',
    collect_mode='strace',

recorder.record_from_collector(collector, timeout_s=60)

# 停止
collector.detach()
summary = recorder.stop()
print(f"Recorded {summary['event_count']} events")
```

## 七、注意事项

### 7.1 文件覆盖与持久化

- **录制文件不会自动覆盖**：每次录制创建新的时间戳目录，不会覆盖已有录制
- **实时落盘**：每条事件写入后立即 `flush()`，进程中断不丢数据
- **录制数据不纳入版本控制**：`records/` 已添加到 `.gitignore`

### 7.2 时间戳处理

- **录制时间戳**：来自原始事件（`RawEvent.timestamp_ns`），录制器不修改
- **回放时间戳**：`VirtualClock` 从配置值开始递增（默认 `1718092800000000000`）
- **meta.yaml 时间**：使用系统时间（`datetime.now()`），格式为 ISO 8601

### 7.3 Agent ID 处理

- **录制时**：使用 `SessionRecorder` 构造时传入的 `agent_id`
- **回放时**：使用 `ReplayEngine.replay()` 传入的 `agent_id`（默认 `replay-agent`）
- **事件补全**：如原始事件未指定 `agent_id`，`EventRecorder` 会使用默认值

### 7.4 性能与限制

| 限制 | 说明 | 影响 |
|------|------|------|
| 事件吞吐 | `EventRecorder` 每条事件 flush 一次 | 高频事件（>1000/s）可能影响性能 |
| 文件大小 | JSONL 文件无压缩 | 长时间录制可能产生大文件 |
| 回放速度 | 逐事件同步处理 | 大量事件（>10000）回放较慢 |
| 并发录制 | 同一时间只能有一个活跃录制会话 | 多次 `[9]` 会提示"已在录制中" |

### 7.5 已知限制

| 限制 | 说明 | 解决方案 |
|------|------|---------|
| `main.py --mode` 不含 `file_replay` | CLI choices 为 `["auto", "simulation", "strace", "ebpf"]` | 通过 `test.py --replay` 或编程接口使用 |
| 回放不支持循环/时间缩放 | `config.yaml` 有 `loop`/`time_scale` 配置但未实现 | 仅影响 `FileReplayCollector` 的高级控制 |
| eBPF 第一版无阻断 | `send_command()` 返回 `False` | 仅观测，不可阻断 |

```bash
# 检查 records/ 目录是否存在
ls records/
```

```bash
# 检查 observer_core 组件是否正常
# 回放日志会输出每个事件的处理状态（PASS/ALERT/BLOCK）
```

```bash
pip list | grep -i yaml
```
