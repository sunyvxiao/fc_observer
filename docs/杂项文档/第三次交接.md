## 4. 已知注意事项

### 4.1 eBPF 第一版仅做观测

根据定稿，eBPF 第一版不支持阻断（`bpf_override_return` 不支持 tracepoint 类型的技术限制）：
- `EbpfCollector.send_command()` 返回 `False`，日志记录 "eBPF 阻断将在第二版实现"
- `EbpfCollector.capabilities().can_block_tier2 == False`
- `EbpfCollector.capabilities().can_block_tier3 == False`

### 4.2 eBPF 加载需要 sudo 权限

`EbpfCollector.attach()` 需要 root 权限加载 eBPF 程序到内核：

```bash
sudo python3 main.py --mode ebpf --pid <TARGET_PID>
# 或者配置能力：
sudo setcap cap_bpf,cap_perfmon+ep $(which python3)
```

### 4.3 strace 配置键名已统一

上一轮交接时已将 `config.yaml` 中的 `strace_binary` 修改为 `strace_bin`，与 `strace_collector.py` 代码中的键名一致。不再存在键名不匹配问题。

### 4.4 demo.py 暂未添加 --mode 参数

`demo.py` 当前硬编码使用 `SimulationCollector`（未支持 `--mode` CLI 参数）。在 Windows 上这是合理的（模拟模式），但如果需要在 Linux 上用 demo.py 演示 eBPF/strace 模式，需后续扩展。当前不影响功能。

### 4.5 时间戳差异（设计特性，非 bug）

| 模式 | 时间源 | 说明 |
|------|--------|------|
| 模拟模式 | `VirtualClock` | 从 `virtual_clock.start_ns` 开始，按 `delay_ms` 推进 |
| strace 模式 | `time.time_ns()` | 真实系统纳秒时间戳 |
| eBPF 模式 | `bpf_ktime_get_ns()` | 内核 monotonic 时钟，从系统启动开始计时 |

`observer_core/` 只读取 `RawEvent.timestamp_ns` 字段值，不关心时钟类型。三种时间源可共存。
